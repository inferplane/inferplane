# 성능 리뷰 반영 및 재측정

작업 시작: 2026-11-06 UTC. 기준 커밋: `49a4c2a`.
기존 미커밋 보안 수정은 보존했으며, 아래 결과는 작업 트리의 추가 변경을 포함합니다.

## 반영한 동작

1. 기본 HTTP 공급자의 응답 헤더 대기를 120초로 제한했습니다.
   이미 시작된 스트림의 전체 시간과 주입된 클라이언트의 제한은 바꾸지 않습니다.
2. 선택 개인정보 마스킹은 기본 꺼짐입니다. `masking.state_file`을 구성하면
   전체 관리자가 콘솔 설정이나 `/admin/masking`에서 켜고 끌 수 있습니다.
   변경은 버전을 검사하고 영속화하며 재시작 후 복원합니다. 시스템 메시지를
   포함한 전체 구조를 검사하며, 필수 개인정보 정책은 이 스위치와 독립적입니다.
3. Responses의 원본 JSON 루트, 변환 가능 여부, strict 도구 검사를 요청 안에서
   재사용합니다. 마스킹 후에는 다시 파싱합니다. 중복 키 검사, 독립적인 개인정보
   검사와 실제 공급자의 전송 검증은 유지하므로 모든 JSON 처리를 제거한 것은 아닙니다.
4. 감사 기록은 최대 64개씩 묶어 디스크에 동기화합니다. 필수 OTLP 출력을 선택하면
   수집기가 전체 묶음을 수신했다고 응답한 뒤 WAL을 정리합니다.
   이전 미전달 이력, 부분 수신, 전송 실패가 있으면 보존합니다. 파일 출력을
   계속 선택하면 해당 파일도 계속 보관합니다. 기존 파일을 소급 삭제하지 않습니다.
5. ADR-045 로컬 금액 저널은 전체 JSON 대신 변경된 항목만 SQLite에 저장합니다.
   디코딩 캐시는 각 트랜잭션에서 소유자·버전·메타데이터를 확인한 뒤 사용합니다.
   FULL 동기화, 정수 비용, 불확실한 사용량 보존과 이전 작성자 차단은 유지합니다.

## 재측정

최종 측정 완료: 2026-11-07 UTC. 다음은 세 번 실행한 결과의 중앙값입니다.

| none | 44.53ms | 38.13ms | 14.4% | 20.20 → 14.20 MiB/op |
| shadow | 47.31ms | 38.59ms | 18.4% | 20.20 → 14.20 MiB/op |

| 감사 기록, 종료·디스크 반영 포함 | 변경 전 | 변경 후 | 처리량 증가 |
| --- | ---: | ---: | ---: |
| WAL | 1750.8µs/기록 | 47.6µs/기록 | 36.8배 |
| WAL + 파일 | 3554.8µs/기록 | 82.2µs/기록 | 43.3배 |

묶음 기록은 대기열이 차는 지속 부하에서 측정했습니다. 단일 기록의 fsync가
같은 비율로 빨라졌다는 뜻이 아닙니다. 수집기로 보내는 네트워크 비용은 제외입니다.

| 금액 저널 예약·정산 한 쌍 | 변경 전 | 변경 후 | 시간 감소 | 할당량 전 → 후 |
| --- | ---: | ---: | ---: | ---: |
| 미완료 0건, 동시 1 | 6.60ms | 3.89ms | 41.0% | 0.89 → 0.29 MiB/op |
| 미완료 256건, 동시 1 | 10.64ms | 4.09ms | 61.6% | 1.61 → 0.39 MiB/op |
| 미완료 1,024건, 동시 1 | 19.67ms | 5.45ms | 72.3% | 4.25 → 0.64 MiB/op |

미완료 1,024건·동시 8 조건의 개별 지연 중앙값(`p50_ns`)도 156.3ms에서 41.7ms로 줄었습니다.
감사는 기존과 동일하게 `-benchtime=1s`, 금액 저널은 `-benchtime=32x`로
재측정했습니다. `after-preliminary-*`는 앞서 실행한 300ms 탐색 결과이며
위 디스크 비교 표에는 사용하지 않았습니다. 게이트웨이는 전후 모두 300ms입니다.

Go 1.26.10, Linux arm64, `CGO_ENABLED=0`, `GOMAXPROCS=4`,
`GOGC=100`, `GOMEMLIMIT` 미설정입니다. 각 조건을 세 번 실행하고 중앙값을
비교합니다. 게이트웨이는 tmpfs, 감사 로그와 금액 저널은 동일 호스트의 XFS를
사용했습니다. 성능 측정은 race 검사와 분리했습니다.

Responses는 네이티브 경로의 0지연 가짜 공급자이며, 실제 모델·네트워크·공급자
직렬화 비용은 포함하지 않습니다. 비동기 감사 종료 시간은 해당 게이트웨이
측정에서 제외됩니다. 감사 로그 전용 측정은 writer 종료와 디스크 반영을 포함합니다.
금액 저널은 완료 영수증 256개를 유지하고, 미완료 예약 0/256/1,024건 상태에서
예약·정산 한 쌍을 측정합니다.

`ns/op`은 처리량의 역수입니다. 특히 동시 실행에서는 개별 요청 지연과 다릅니다.
`B/op`은 누적 메모리 할당량이며 상주 메모리가 아닙니다. 공유 호스트의 짧은
합성 측정이므로 운영 p95/p99, OTLP 수집기 처리량, 실제 모델 품질이나 HA의
검증 결과로 해석할 수 없습니다. 마스킹을 켰을 때의 정규식 비용도 남아 있습니다.

원시 출력, 실행 조건, 바이너리·소스 해시와 디스크 측정 코드는
[측정 자료](performance-hardening-results-2026-11-06/after-metadata.json)에
함께 보관합니다.

## 검증과 업그레이드

중복/불투명 JSON 거부, 원본 바이트 보존, 스트림 지속, 관리자 인증·버전 충돌·
재시작 복원, 필수 마스킹 독립성, OTLP 부분 수신 보존, 저널의 롤백·손상·
재시작·작성자 차단 회귀 테스트를 추가하거나 실행했습니다.

- 두 실행 파일의 `CGO_ENABLED=0` 빌드 통과.
- `go test ./... -race`: 테스트가 있는 68개 패키지 통과. 최종 리뷰 중 수정한
  `cmd/mayu`·`responsesapi`의 전체 race 검사도 다시 통과.
- `go vet ./...`, 추적 중이거나 새로 작성한 Go 파일 847개의 gofmt 검사,
  `git diff --check` 통과. 사용자 벤치마크 캐시의 외부 Go 테스트 자료는 제외.
- `bash tests/run-all.sh`: 70개 검사 통과.
- 영문·한글 문서 48쌍 및 ADR 색인 2개 검사 통과.

테스트는 설치된 의존성과 로컬 가짜 HTTP/gRPC 서버만 사용했습니다.

금액 저널 v1은 시작 시 v2로 원자적으로 이전하며, 기존 시작 절차대로 이전
권한을 폐기합니다. **구버전 바이너리는 v2 저널을 열 수 없습니다.**
다운그레이드를 위해 저널을 삭제하거나 오래된 사본으로 덮어쓰면 안 됩니다.
운영 배포나 실행 중인 설정은 이 작업에서 변경하지 않았습니다.
