# 반복 호출과 CLI 호환성 {#repeated-calls-and-cli-compatibility}

**2026년 10월 20–21일 측정 · Claude Code 2.1.304 · Codex 0.163.0.** [모델별 성능 결과](models.md)에 반복 관측을 추가했습니다. [결과 JSON](../assets/data/client-compatibility.json)은 Bedrock 직접 호출, inferplane을 거친 실제 CLI 과제, 로컬 프로토콜 모의 시험을 구분합니다. 각 표에서 모델 이름으로 검색할 수 있습니다.

**입력 점유율 98%**는 선언된 컨텍스트 창 대비 보고된 입력 토큰의 비율입니다. 성공률 98%라는 뜻이 아닙니다. 성공/호출은 실제 호출된 시도의 결과이며, 예산 차단이나 전송 미지원으로 호출하지 않은 기록은 제외합니다. 과제 실패율도 이 호출 수를 분모로 계산합니다. HTTP·스트림 오류율은 HTTP 비정상 상태, 오류 이벤트 또는 스트림 미완료의 비율입니다. 과제 실패율에는 회수 오답과 미완료도 포함합니다. HTTP 200이어도 과제는 실패할 수 있습니다. 출력 한도에 닿았더라도 정상 종료된 응답에서 값 3개를 모두 찾았다면 회수 과제는 성공으로 셉니다.

아래 요약은 공개된 관측만 집계합니다. API 행의 단위는 직접 호출이고, CLI 행은 모델 호출 전 거절도 포함한 시도 수와 과제 성공 수를 셉니다. CLI 오류 요청 수의 분모는 재시도를 포함한 게이트웨이 요청 수입니다. 비용 미확인 요청이 있으면 표의 확인된 비용만으로 전체 지출을 계산할 수 없습니다.

TTFT와 E2E는 **성공한 과제만의 중앙값**입니다. 청구 출력 tok/s는 출력 토큰을 요청 전체 시간으로 나눈 값으로, 입력 처리 시간과 비공개 추론 토큰이 포함될 수 있습니다. 지속적인 생성 속도나 실패한 과제의 성능 점수가 아닙니다. 전체 호출 비용에는 사용량이 확인된 실패 호출도 포함하며, `+ ? (n)`은 비용 미확인 호출 n건을 뜻합니다. 설정 단가에 따른 추정치이며, 청구서 금액이 아닙니다. 미확인 비용이 있으면 완전한 총비용도 아닙니다.

각 모델은 라운드 안에서 순차 호출하고, 서로 다른 모델은 최대 3개까지 동시에 실행합니다. 라운드마다 모델 순서를 섞습니다. 동일 프롬프트 반복으로 캐시가 적용될 수 있으며, JSON의 토큰 유형별 수량에서 실제 캐시 읽기·쓰기를 확인할 수 있습니다. 짧은 입력과 긴 입력은 길이와 채움 문자의 종류가 함께 달라지므로 순수한 길이 효과로 해석하면 안 됩니다. 2회나 5회만으로 SLA를 추정할 수 없습니다. 독립 베르누이 시행을 가정해도 5/5 성공의 Wilson 95% 신뢰구간 하한은 약 56.6%이며, 캐시를 공유하는 반복 호출은 독립적이지 않을 수 있습니다. 관측이 5개면 최근접 순위 p95는 최댓값과 같으므로 표에는 중앙값을 사용합니다.

## 실제 코딩 클라이언트 과제 {#actual-coding-client-tasks}

설치된 CLI를 커밋 `a24b6dd`를 기반으로 빌드한 격리 inferplane 게이트웨이에 연결했습니다. Codex는 **상태를 보관하지 않는 Responses 브리지**, Claude Code는 Messages 변환 경로를 사용합니다. 각 모델의 네이티브 Responses 전송까지 검증한 결과는 아닙니다. 시험 도중 도구 없는 자동 압축 요청을 허용하는 수정을 적용했으며, 각 실행의 빌드 단계를 기록했습니다. 이 제한적인 수정은 일반 smoke·코딩 요청을 바꾸지 않습니다. API 시험과 시간대가 겹치므로 이 CLI 실행 시간으로 게이트웨이 오버헤드를 비교하지 않습니다.

Smoke 과제는 정해진 표식 응답을 3회 반복합니다. 성공 검사는 표식 포함 여부를 확인하며, 다른 문구가 붙었는지까지 검사하지는 않습니다. 코딩 과제는 격리 파일을 읽고, 덧셈 함수의 뺄셈 오류를 수정하고, Python 단위 테스트를 실행한 다음 파일 고유 표식을 반환해야 합니다. 테스트 파일 내용 유지, 테스트 통과, 도구 호출 관측, 표식 회수, 정상 CLI 종료를 모두 만족해야 성공입니다. 코딩 과제는 셀마다 1회입니다. `—`는 가격 미설정 등으로 유효한 실제 관측이 없다는 뜻이며, 지원 불가를 뜻하지 않습니다.

Qwen3 Coder Next에서 Claude Code는 기본 **200,000**, `[1m]` 사용 시 **1,000,000**, `CLAUDE_CODE_MAX_CONTEXT_TOKENS=256000` 사용 시 **256,000**을 보고했습니다. 접미사는 전송 모델 ID에서 제거되고 `context-1m-2025-08-07` 베타 헤더가 추가됩니다. 서버의 256K 창이 1M으로 커지는 것은 아닙니다.

Claude Code에는 명시적 환경변수 설정도 있으므로 `[1m]`만이 유일한 방법은 아닙니다. [공식 모델 설정 문서](https://code.claude.com/docs/en/model-config)에 따른 우선순위는 조건에 따라 달라집니다.

- 인식되지 않는 제공자 모델에 `[1m]`가 없으면 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`로 가정 창을 정하면서 사전 압축을 유지할 수 있습니다.
- 같은 모델에 `[1m]`가 있으면 접미사가 우선하며, 환경변수를 적용하려면 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`도 설정해야 합니다.
- 인식되는 Claude 모델 이름은 처리가 다릅니다. 명시적 재정의에 `DISABLE_COMPACT`가 필요할 수 있는데, 이 설정은 압축을 비활성화합니다. 제공자 이름만으로 추정하지 않고 위 표에서 정확한 시험 모델 ID의 관측값을 확인해야 합니다.

Codex는 `model_context_window`, `model_auto_compact_token_limit`, `model_catalog_json`을 지원합니다. [설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)를 참고하세요. 같은 Qwen 모델에서 사용자 제공자 기본값은 **258,400**, 창을 256,000으로 명시하면 클라이언트의 95% 계산이 적용된 **243,200**, 시험한 inferplane 런처는 보수적인 80% 카탈로그 정책에 따라 **204,800**을 보고했습니다. 마지막 값은 클라이언트의 유효 창이지 서버 선언을 줄인 값이 아닙니다. 로컬 컨텍스트 프로필이나 상속된 전역 설정에 따라 달라질 수 있으며, 이 시험은 깨끗한 설정을 사용했습니다.

## 실제 CLI를 통한 긴 입력 {#long-input-through-the-actual-clis}

아래 각 행은 실제 설치 CLI의 합성 회수 시도입니다. 모델 호출 전 클라이언트에서 거절된 경우도 표시하며, 이때 입력 토큰은 관측되지 않습니다. Claude Code는 `[1m]`를 사용하고 프롬프트 부가분을 고려해 서버 선언 창의 약 98%를 목표로 합니다. Codex는 런처 유효 창 80%의 약 98%에서 프롬프트 여유분을 뺀 값, 즉 서버 선언의 약 78.4%를 목표로 합니다. 실제 제공자 입력 토큰 수를 표시하며, 서로 작업량이 다르므로 동일 조건의 순위로 비교하면 안 됩니다. CLI 경과 시간에는 시작·재시도·종료 시간이 포함됩니다. 요청 수와 별도 가드 거절 수를 함께 표시하며, 가드 거절이 있는 시간 초과는 제공자만의 시간 초과로 해석할 수 없습니다.

최초 긴 입력 시도 세 건은 예산 가드가 모델 호출 전에 중단했습니다. 이후 예산을 확보한 시도는 별도 행으로 남겼습니다. Kimi K3는 979,261 입력 토큰에서 모든 값을 회수했고, Sonnet 5.5는 업스트림 오류 후 후속 요청이 실험 가드에 막힌 상태에서 시간 초과됐습니다. Claude Fable 5.1은 유료 긴 입력 CLI 관측이 아직 없습니다. 이 공백은 모델 호환성 실패를 뜻하지 않습니다.

## 컨텍스트 한도와 압축 오류 구분 {#context-limit-and-compaction-errors-are-different}

자동 압축 시작값은 모델 창보다 작게 설정될 수 있습니다. 그 부근에서 오류가 났다는 사실만으로 서버 창의 한도라고 판단할 수 없습니다. 업스트림 오류 코드, 전송 경로, 보고된 입력 사용량, 실패한 작업을 함께 확인해야 합니다.

| 관측 | 확인할 수 있는 사실 |
| --- | --- |
| 명시적 컨텍스트 창 거절 | 시험 경로에서 해당 요청이 너무 큽니다. 사용량이 없으면 정확한 경계는 미측정 상태입니다 |
| `conversation_blocked` / `this conversation cannot be continued` | 제공자가 대화를 거절했습니다. 명시적인 길이 초과 오류는 아닙니다 |
| 일반 응답과 후속 압축에서 같은 거절 | 압축도 실패했습니다. 가정 창을 늘리면 해결된다는 증거는 없습니다 |
| `no policy-permitted compatible Responses target` | 게이트웨이 승인·변환 단계에서 허용된 호환 대상이 없습니다. 경로 기능과 요청 기능을 확인해야 합니다 |

## Astra 자동 압축 오류 재현과 수정 {#reproduced-astra-automatic-compaction-failure-and-fix}

별도의 2턴 시험에서 `model_auto_compact_token_limit=180000`으로 설정했습니다. 첫 턴에 약 204K의 합성 입력을 보내고 다음 턴에서 자동 압축을 유도했습니다. 수정 전에는 첫 턴이 완료됐지만 압축 요청은 제공자 호출 전에 게이트웨이 HTTP 400으로 거절됐습니다. Codex가 `tools:[]`와 함께 `parallel_tool_calls:false`를 보냈고, 실행할 도구가 없는데도 Responses 변환 검증기가 이를 거절한 것이 원인이었습니다.

수정은 도구가 생략되거나 null 또는 빈 배열일 때만 이 설정을 허용합니다. 실제 도구 선언이 있으면 기존 지원 조건을 유지하며, 원격 상태·불투명 추론·미지원 추론 모드도 계속 거절합니다. 네이티브 Responses 전달은 그대로입니다. 모델 창이나 사용자의 압축 기준을 늘리는 변경이 아니라 요청 변환 호환성 수정입니다.

수정된 격리 환경에서 두 번 모두 압축 완료 이벤트와 다음 응답을 확인했습니다. 첫 입력은 **204,608 / 204,614**, 압축 입력은 **201,604 / 201,610**, 다음 턴 입력은 **44,874 / 44,872**토큰이었습니다. 설치된 런처와 수정된 실제 로컬 서비스에서도 **204,602 → 201,607 → 44,847**토큰으로 성공했습니다. 로컬 경로는 `global.` 별칭을 사용하며 공개 데이터에 요청한 모델 ID를 별도로 보존합니다. 모두 합성 이력으로 실제 자동 압축을 실행한 결과이며 단순히 긴 첫 턴만 성공한 결과가 아닙니다.

압축도 별도의 모델 요청입니다. 두 수정 후 격리 실행에서 압축 요청 비용은 각각 **$2.531295 / $2.530970**, 다음 턴 비용은 **$0.561320 / $0.561295**였습니다. 첫 턴·압축·다음 턴을 합친 비용은 **$5.650710 / $5.650435**입니다. 보고된 캐시 쓰기 토큰을 포함한 설정 단가 추정치이며 청구서 금액은 아닙니다. 수정 전 실행은 압축 전에 거절되어 작업량이 다르므로 총비용만으로 비용 증가나 성능 저하를 비교할 수 없습니다.

무과금 회귀 시험도 설치된 Codex 앱 서버와 로컬 모의 응답으로 압축 이벤트를 실행합니다. 변환 테스트는 도구 없는 압축 허용과 실제 도구·미지원 상태 거절을 함께 검증합니다. 실측이 확인한 범위는 추론을 끈 해당 Astra 브리지 경로입니다. 다른 모든 모델의 압축, 개인 이력 재개, 제공자 변경, 다른 추론 모드, MCP 서버, 다중 에이전트 작업은 검증 범위 밖입니다. 게이트웨이의 [배포·회계 프로필](../getting-started/deployment-profiles.md) 조건도 계속 적용됩니다.
