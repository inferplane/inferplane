# 모델별 성능 {#model-performance}

**측정일: 2026년 10월 19일 · 49개 모델 · Bedrock 직접 호출.** inferplane의 모델 설정에 참고할 수 있는 자료이며, 게이트웨이 오버헤드나 모든 모델의 네이티브 Converse 호환성을 입증하지 않습니다. 기록된 전송 경로는 모델에 따라 Bedrock Runtime 또는 Mantle입니다. inferplane 측정은 [게이트웨이·관리자 결과](index.md)를 참고하세요.

[반복 호출과 Claude Code·Codex 호환성](clients.md)에서 모델별 반복 성공률, 실제 코딩 과제와 클라이언트 창 설정을 확인할 수 있습니다.

## 컨텍스트 용량과 요청 비용 {#context-capacity-and-request-cost}

각 행은 해당 모델에서 **선언 창 크기의 100% 이내로 회수에 성공한 가장 큰 입력**입니다. 입력 토큰에는 캐시를 한 번만 포함합니다. 입력의 약 10%·50%·90% 위치에 삽입한 세 값을 모두 회수해야 성공입니다. 출력 순서나 JSON 형식은 엄격히 요구하지 않습니다.

**26개 모델이 점유율 95–100%에 도달했습니다.** 이보다 낮은 값은 해당 모델의 전체 창 사용을 이 자료로 입증하지 못했다는 뜻입니다. 대시는 조건에 맞는 회수 성공이 관측되지 않았다는 의미이며 컨텍스트를 지원하지 않는다는 뜻이 아닙니다. 창 크기는 측정 당시 목록이며 실시간 카탈로그가 아닙니다.

## 입력 조건별 과제 실패 {#task-failures-by-input-condition}

분모는 **각 조건에서 실제 실행한 직접 호출 수**이며 포함된 모델당 한 번씩 호출했습니다. 호출하지 않은 기록은 제외합니다. 의도적으로 다른 작업 부하를 하나의 운영 게이트웨이 오류율로 합치면 안 됩니다. 실패 중에는 전송 장애가 아니라 공급자 거부나 예상된 용량 한계 검사도 있습니다.

102% 조건에서는 **38건을 호출**했고 별도 4건은 실행하지 않았습니다. 약식으로 선언된 창 크기를 초과한 요청의 수용은 제한 우회나 무제한 창을 뜻하지 않습니다. K/M 선언, 서버 한계, 토크나이저 기준이 다를 수 있습니다.

HTTP 200만으로 성공을 판정하지 않습니다. 콘텐츠 필터, 빈 응답, 출력 한도, 스트림 미완료, 회수 오답도 과제 실패입니다. 사용량 누락은 무료 호출의 근거가 아닙니다. 리전·접근 실패는 시험 계정과 리전에서의 관측이며 전 세계 모델 가용성을 뜻하지 않습니다.

## 측정값 해석 {#reading-the-evidence}

| 지표 | 정의 |
| --- | --- |
| 선언 창 크기 | 기록된 모델 카드 숫자. K/M은 1,000/1,000,000으로 변환하며 원문도 JSON에 보존 |
| 점유율 | 관측한 전체 입력 토큰 ÷ 선언 컨텍스트 창. 출력은 분자에 포함하지 않음 |
| TTFT | 첫 사용자 가시 텍스트까지의 시간. 수신하지 못했다면 값 없음 |
| E2E | 응답 스트림이 끝날 때까지의 시간 |
| 요청 비용 | 관측된 캐시 분류와 출력을 포함한 설정 가격 기반 추정 |
| 성공 | 과제 출력 규칙에 맞는 생성 완료, 또는 삽입한 세 값을 모두 포함한 회수 완료 |

목록에는 호출 성공이 없는 모델까지 기록된 목적지 49개가 모두 포함됩니다. JSON에는 실패 분류와 기록 가격을 보존하고 원시 프롬프트·응답은 제외합니다. 가격과 카탈로그는 해당 날짜의 관측이며 모델 ID만으로 가격, 개인정보 보호, 과제 품질을 보장할 수 없습니다.
