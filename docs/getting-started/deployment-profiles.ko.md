# 배포 프로파일 선택 {#choose-a-deployment-profile}

복제본 수보다 회계와 가용성 조건을 먼저 선택하세요. 모든 프로파일은 알파이며 백엔드를 활성화하는 것만으로 운영 환경 검증이 완료되지는 않습니다.

| | 로컬 SQLite | 노드별 영속 금전 예산 · ADR-045 | 공유 Postgres · ADR-046 |
| --- | --- | --- | --- |
| 평가 대상 | 게이트웨이 하나 | 관리되는 개발자별 게이트웨이 | 공유 게이트웨이 집합 |
| 키·팀 기록 | 로컬 SQLite | 로컬 SQLite | 공유 Postgres |
| 정책 금전 예산 | 로컬 메모리, 선택적 기존 CP 허용량 | 전역 Postgres 권한과 비공개 로컬 예약 | 원자적 Postgres 예약 |
| 요청률·토큰 할당량 | 로컬 | 로컬 | 공유 |
| 요청 승인 시 DB 접근 | 로컬 저장소만 | 로컬 비공개 저널, 권한은 비동기 발급 | 공유 Postgres에 동기 접근 |
| 여러 게이트웨이 | 각각 독립된 한도 | 정책 금전만 공유, 나머지는 로컬 | 공유 승인 메커니즘 |
| 설정 | [빠른 시작](quickstart.md) | [영속 예산](../durable-budgets.md) | [공유 거버넌스](../shared-governance.md) |

ADR-045는 독립 실행·키별 로컬 금전 한도를 전역화하지 않습니다. 기존 제어 영역의 허용량은 영속적인 예산 예약이 아닙니다. ADR-046에서는 모든 게이트웨이와 제어 영역이 같은 권한 데이터베이스·스키마를 사용해야 합니다.

## 장애 동작 이해 {#understand-outages}

| 상황 | 로컬·기존 방식 | ADR-045 | ADR-046 |
| --- | --- | --- | --- |
| CP HTTP 접근 불가 | 독립 실행에는 CP 의존성 없음. 연결된 경우 설정된 조건 적용 | 기존 권한만 사용, 정책·준비 상태·유효 기한 내에서만 허용 | 유효한 바인딩·정책과 접근 가능한 DB가 있으면 승인 가능 |
| 권한·공유 DB 접근 불가 | 공유 승인 DB 의존성 없음 | 기존 로컬 권한만 사용, 보충 불가 | 새 키 조회·요청 승인 거부 |
| 게이트웨이 재시작 | 메모리 카운터 초기화 | 저널 복구 시 미확정 의무를 보수적으로 유지 | 공유 기록 유지, 불명확한 허가는 예약 상태 유지 |
| 권한 소진·만료 | 로컬 정책 의미 적용 | 거부, 자동 환급 없음 | 거부, 자동 환급 없음 |

`require_sync`는 최초 정책 수신을 요구합니다. `max_policy_age`는 오래된 정책으로 요청을 승인하지 못하게 할 수 있습니다. 영속 권한과 공유 바인딩에는 자체적인 필수 초기 검사가 있습니다. 유효한 잔액도 감지된 신원·정책 불일치를 우회할 수 없습니다.

생성이 거부되어도 토큰 계산은 로컬 HTTP 200을 유지합니다. 게이트웨이, 자격 증명, 저장소, 공급자의 가용성은 별도 의존성입니다. 어느 프로파일도 무제한 오프라인 운영이나 무조건적인 가용성을 보장하지 않습니다.

## 사용자 식별을 명시적으로 적용 {#add-identity-deliberately}

모든 프로파일은 선택적 [검증된 사용자 식별](../verified-identity.md)을 지원합니다. 선택 모드는 기존 회계 참조를 유지하고, 필수 모드는 레지스트리 바인딩을 집행합니다. 저장소를 공유한다고 필수 신원 검증이 자동으로 켜지지는 않습니다.

마이그레이션은 폐기된 키에만 남은 소유자까지 포함해 과거 계정 참조와 미해결 금전 의무를 보존해야 합니다. 필수 모드는 저장되는 변경이며 자유롭게 되돌릴 수 있는 기능 토글이 아닙니다.

## 운영 범위 결정 {#select-an-operating-boundary}

파일럿의 사용자, 게이트웨이 프로파일, 허용 모델, 지출 노출 범위, 복구 책임자, 종료 기준을 정하세요. 남은 검증은 [상용화 준비도](../operations/production-readiness.md)에서 확인할 수 있습니다.
