# 보안 경계 {#security-boundaries}

inferplane은 자격 증명을 분리하고 게이트웨이에서 설정된 제어를 적용합니다. 집행은 신뢰할 수 있는 배포 경계, 올바른 신원·공급자 선언, 선택한 저장소 프로파일에 의존합니다.

## 자격 증명과 관리 {#credentials-and-administration}

공급자 비밀은 서버의 `env:`/`file:` 참조로 사용합니다. 커밋하는 설정에 비밀 값을 넣지 마세요. 가상 키는 해시로 저장되고 발급 시 평문이 한 번만 표시됩니다. 가상 키를 업스트림 공급자 자격 증명으로 전달하지 마세요.

관리 접근은 비공개로 유지합니다. 정책 쓰기와 자격 증명 중개에는 전용 자격 증명이 필요합니다. 하트비트 토큰은 관리자·중개 토큰이 아닙니다. 현재 관리 검사는 조직·팀 범위 역할 6개의 전체 권한 모델을 구현하지 않습니다.

OIDC 신원은 검증된 발급자·주체 클레임에서 나와야 합니다. 임의의 키 소유자 문자열이나 이메일은 필수 [검증된 신원](../verified-identity.md)과 같지 않습니다. 저장소·DSN 접근은 특권 관리 작업입니다.

## 호스트와 네트워크 신뢰 {#host-and-network-trust}

게이트웨이 호스트를 제어하는 사람은 로컬 공급자 자격 증명, 중개 토큰, 단기 세션을 얻을 수 있습니다. 중개는 상시 Bedrock IAM 자격 증명을 제거하지만 침해된 개발자 장비의 우회를 막아 주지는 않습니다. 반드시 게이트웨이를 통과해야 한다면 인프라에서 공급자 직접 접근을 제한하세요.

관리·메트릭 엔드포인트를 제한하고 원격 트래픽에는 TLS를 사용합니다. 공유 승인은 접근·인증 가능한 Postgres가 필요하며 장애 시 거부합니다. 공급자 목적지와 네트워크 외부 통신 정책을 함께 구성하세요. 운영자가 붙인 “internal” 라벨만으로 실제 비공개 경계가 생기지 않습니다.

## 개인정보와 감사 {#privacy-and-audit}

민감 정보 탐지기는 유한한 휴리스틱입니다. 필요한 데이터 종류와 거부 경로를 검증하세요. 모든 개인정보 탐지나 규정 준수를 추론하면 안 됩니다. 마스킹·프로토콜 변환은 요청 바이트와 캐시 동작을 바꿀 수 있습니다.

요청·응답 본문 수집은 선택적이며 별도의 암호화·접근·보존 제어가 필요합니다. 감사 해시 체인은 불일치를 탐지합니다. 외부 WORM 저항성은 [앵커 저장소와 IAM](../runbooks/audit-anchoring.md)에 추가로 의존합니다. 각 인스턴스 구간을 보존하세요.

## 취약점 신고 {#report-a-vulnerability}

비공개 신고는 [저장소 보안 정책](../../SECURITY.md)을 따르세요. 자격 증명, 원문 프롬프트, 신원 선언, 악용 가능한 세부 내용을 일반 이슈로 공개하지 마세요. 공개 이슈 템플릿은 민감 정보를 제거한 일반 결함에 사용합니다.
