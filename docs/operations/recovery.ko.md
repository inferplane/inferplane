# 업그레이드와 복구 {#upgrade-and-recover}

변경 중에도 신원, 금전 의무, 감사 증거를 보존하세요. 새 권한이나 지출이 존재하면 오래된 DB 스냅샷으로 되돌리는 것만으로는 안전한 롤백이 되지 않습니다.

## 업그레이드 계획 {#plan-an-upgrade}

1. 현재·후보 커밋과 이미지를 고정하고 변경된 ADR·설정 스키마를 읽습니다.
2. 프로파일, 권한 네임스페이스, 정책 세대, 참여 바이너리, CRD 버전, 신원 선언을 기록합니다.
3. 격리된 스테이징에서 합성 신원·일회용 상태·가짜 공급자로 검증한 후 통제된 실제 모델 시험을 수행합니다.
4. 관련 저장소를 일관되게 백업하고 격리 환경에서 복원을 확인합니다. SQLite는 적절한 백업 기능이나 중지된 서비스를 사용해 부속 파일을 포함하고, 비공개 노드 저널·감사 구간·모든 Postgres 신원/정책/권한 테이블을 보존합니다.
5. 비호환 변경 시 이전 쓰기 주체와 게이트웨이를 중지·차단하는 방법을 정합니다. 발급된 권한을 추적하세요. 노드를 중지했다고 잔액이 미사용이라는 뜻은 아닙니다.
6. 호환 바이너리·CRD를 배포하고 준비 상태, 키 교체, 거부 사례, 관측 사용량, 불확실성 유지, 감사 검증을 확인합니다.

지원되는 공급자·모델·가격 토폴로지는 SIGHUP으로 다시 읽을 수 있습니다. 백엔드, 신원 선언, 권한 모드, 노드 ID, 저널 경로, 리스너 변경은 재시작이 필요합니다. 스키마·프로파일 마이그레이션은 핫 리로드가 아닙니다.

## 장애 대응 {#outage-response}

| 장애 | 안전한 대응 |
| --- | --- |
| CP 접근 불가 | 정책·권한 전달 복구. 설치된 준비 상태·정책 만료·권한 기한 준수 |
| 공유 Postgres 접근 불가 | 검증된 DB 경로 복구. 신규 공유 승인은 거부됨 |
| 노드 저널 접근 불가 | 영향받는 승인 중지. 저널과 부속 파일 보존 |
| 불완전 스트림·사용량 불명 | 미확정 의무를 예약 상태로 유지. 관측값과 공급자 증거 비교 |
| 감사 저장 대상 장애 | 버퍼 소진 전에 복구. WAL 바이트 보존 |
| 노드 유실 | 중앙 권한을 확정된 예약으로 유지. 만료는 환급 근거가 아님 |

ADR-045는 모든 조건 안에서 유효한 기존 로컬 권한만 사용할 수 있습니다. ADR-046의 신규 공유 승인은 항상 DB가 필요합니다. CP HTTP 장애와 DB 장애는 별도로 시험하세요.

## 권한 상태를 안전하게 복원 {#restore-authority-safely}

오래된 정책·신원·권한 행을 복원하면 백업 이후 사용한 예산이 되살아날 수 있습니다. 쓰기 주체를 차단하고 복원 상태를 공개하기 전에 백업 이후 모든 의무를 확인하세요. 완료된 지출, 열린 권한, 대기 중인 공유 허가, 지연 보고를 조정에 포함합니다.

미해결 권한을 확정할 수 없으면 영향받는 윈도를 동결 상태로 유지하세요. 접근할 수 없는 게이트웨이나 만료된 권한은 미사용 잔액의 증거가 아닙니다. 카운터 절단, 허가·권한 행 삭제, 실행 중 저널 복제, 새 계정 참조로 재발급하여 서비스를 복구하지 마세요.

자동 환급·조정 API나 일반적인 무중단 롤백 절차는 제공하지 않습니다. [영속 권한](../durable-budgets.md), [공유 저장소](../shared-governance.md), [신원 마이그레이션](../verified-identity.md)의 구체적인 계약을 따르세요.

## 운영 전에 필요한 증거 {#evidence-needed-before-production}

실제 복원·장애 조치 시험에서 복구 시간과 허용 데이터 손실을 기록하세요. CP 프로세스 장애와 DB 장애, 충돌 후 유지되는 불확실성, 과거 잔액을 보존하는 신원 교체를 포함합니다. 이는 직접 측정해야 할 인수 기준이며 이 문서가 제공하는 보장이 아닙니다.
