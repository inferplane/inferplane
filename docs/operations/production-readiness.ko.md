# 상용화 준비도 {#production-readiness}

**현재 평가는 범위를 제한하고 운영자가 감독하는 파일럿에 적합한 단계이며, 엔터프라이즈 정식 운영 준비 완료는 아닙니다.** 2026-09-19에 병합된 `main` 기준선 `b039b75`를 검토했습니다. 프로젝트는 명시적으로 알파 상태를 유지합니다.

영속 금전 권한, 공유 Postgres 승인, Responses/Codex 연동, 민감 정보 라우팅, 검증된 신원 메커니즘은 구현되어 있습니다. 이 기능들이 전혀 없다는 평가는 이전 체크아웃에 해당합니다. 구현의 존재만으로 운영 배포가 검증된 것은 아닙니다.

## 이미 확보된 기반 {#what-is-already-established}

| 영역 | 저장소 근거 | 입증 범위 |
| --- | --- | --- |
| 예산 권한 | [ADR-045](../decisions/ADR-045-durable-budget-authority.md), `internal/authority/local`, `internal/authority/pgstore` | 영속 권한과 시도별 보수적 예약 메커니즘 |
| 공유 집행 | [ADR-046](../decisions/ADR-046-shared-governance.md), 공유 저장소·게이트웨이 테스트 | 동기 DB를 사용하는 키·요청률·토큰·금전 승인 |
| 검증된 신원 | [ADR-048](../decisions/ADR-048-verified-identity-bindings.md), 레지스트리·마이그레이션 테스트 | 등록된 회계 참조를 유지하는 선택적 바인딩 |
| 클라이언트 호환 | Responses 픽스처·설치된 클라이언트 시험, [실행 도구](../codex-launcher.md) | 시험한 프로토콜·클라이언트 경로. 모든 실제 모델을 의미하지 않음 |
| 개인정보·라우팅 | [라우팅 가이드](../policy-routing.md), 탐지·라우터 테스트 | 선언된 탐지기·공급자 기능 범위의 실패 시 거부 조합 |
| 지속 검증 | [CI 워크플로](../../.github/workflows/ci.yml) | 정적 빌드, race/vet/형식, CRD, 필수 DB, 하네스, 취약점 검사 |

DB 결과 검사는 필수 테스트의 누락·스킵을 거부합니다. Postgres 없이 실행한 로컬 시험을 DB 검증으로, 녹색 CI를 실제 부하·장애 조치 벤치마크로 간주하지 않습니다.

## 남은 릴리스 조건 {#remaining-release-gates}

| 조건 | 현재 차이 | 완료에 필요한 증거 |
| --- | --- | --- |
| 관리 신뢰 | 조직·팀 범위의 역할 6개와 완전한 영속 변경 증거 미완료 | 엔드포인트 권한 지도, 부정 권한 시험, 행위자·전후 상태·세대의 트랜잭션 연계 기록 |
| 사용자 예산 계약 | 완전한 프리미엄 풀·총한도 동작 미완료 | 기기 간 동일 신원, 승인된 호환 폴백 또는 거부, 잔액 부활 방지 |
| 신원 배포 | 선택적 구현이며 과거 바인딩·필수 모드 전환은 운영 작업 | 폐기된 키에만 남은 이력까지 매핑, 교체·마이그레이션·복구 시험 |
| 복구 | 미확정 의무 유지, 자동 조정 절차 없음 | 안전한 진단, 의무 보존, 오래된 백업 복원 검증 |
| HA·용량 | 프로파일·공유 저장소는 존재, 운영 검증 미완료 | 처리량·지연·DB 장애 조치·장애 영역·재시작 실측 |
| 공급자·개인정보 검증 | 유한한 탐지기, 선언된 경계, API별 제어 | 버전별 클라이언트·모델 시험, 금지 외부 호출, 가드레일 적용·거부, 변환 증거 |
| 릴리스 공급망 | 검토 기준선에 공개 서명 릴리스 워크플로·산출물 채널 없음 | 재현 가능한 고정 산출물, 검증 절차, 단계적 배포·롤백 증거 |

정식 기준은 [엔터프라이즈 계약](../enterprise-strategy.md)입니다. 알파라는 이름만 바꾸지 말고 이 기준을 증거로 충족해야 합니다.

## 파일럿 인수 기준 {#pilot-acceptance}

사용자, 트래픽 종류, 공급자 계정, 최대 지출 노출, 책임 운영자를 합의하세요. [배포 프로파일](../getting-started/deployment-profiles.md)을 하나 선택하고 개인 단위 제어를 평가한다면 필수 신원 검증을 설정합니다.

허용·금지 모델 호출, 키 교체, 공유 모드의 한도 근처 동시성, 중단된 스트림, 정책·신원 불일치, CP 장애, DB 장애, 백업 복원을 검증하세요. 실제 공급자 호출을 권한·사용량·감사 기록과 대조합니다. 재시도와 콜드 캐시 쓰기를 포함한 총비용·작업 성공률을 측정하세요.

종료 판단도 정해 두세요. 기준을 충족한 경우에만 확대하고, 실패하면 신규 승인을 중지하고 증거를 보존합니다. 이 저장소는 공개 SLA, 관리형 서비스, 규정 준수 인증을 확립하지 않습니다.
