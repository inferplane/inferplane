## [Unreleased]

### Added
- **OpenAI Responses API ingress** (`POST /v1/responses`, `internal/server/responsesapi`): the wire current Codex REQUIRES for custom providers (Codex removed `wire_api: "chat"`; discovered by running the real client, openai/codex discussion #7782). Implemented as an ADAPTER over the Chat Completions ingress — the request is translated to the chat wire and served by the existing pipeline, so key auth, RBAC, governance (reserve/settle included), PII policy, routing/fallback, and the audit chain apply identically and can never drift; the response (JSON or SSE) is translated back, including split tool-call delta reassembly and `response.created`/`output_item.added`/`output_text.delta`/`output_item.done`/`completed` event framing with real usage. Built and tested against Codex 0.152.1's own captured request (the trimmed capture is the package's test fixture); untranslatable params (reasoning replay, non-function tools, `include`, `store`, `prompt_cache_key`, …) are dropped WITH disclosure (`x-inferplane-responses-params-dropped`), never silently. Real `codex exec` now completes turns through mayu with zero protocol errors — all three target coding agents (Claude Code, OpenCode, Codex) are client-verified (`docs/verification/coding-agents.md`).
- **Measured head-to-head benchmark vs LiteLLM and Portkey** (`benchmarks/gwcompare`): the real binaries of all three gateways against one instant mock upstream on loopback. mayu's full governed hot path adds +0.8ms p50 (non-streaming, c=1) where Portkey OSS 1.15.2 adds 2.5× that and LiteLLM 1.99.0 adds 9.4× that; on streaming first-content time LiteLLM adds 17× mayu's overhead (Portkey OSS errored on all streaming requests under plain Node in this environment — recorded, not hidden). Reproduction steps and caveats in the harness README; `docs/comparison.md` §5 now cites measured numbers instead of "unbenchmarked".
- **Real coding-agent client verification** (`docs/verification/coding-agents.md`): Claude Code 2.1.258 and OpenCode 1.18.26 each completed a real turn through a running mayu with a virtual key — served, settled in integer µUSD, hash-chain-audited (`mayu audit verify` green), zero client-side patches. Codex 0.152.1 initially exposed a real gap — current Codex removed the Chat Completions wire for custom providers and requires the OpenAI Responses API (a finding only a real client could surface; the Chat-shape Codex fixtures pin a wire current Codex no longer speaks) — closed the same day by the `/v1/responses` ingress above, after which `codex exec` completes turns through mayu with zero protocol errors.
- **Atomic budget reserve/settle** (strategy Phase 1): every BLOCK-posture budget window (team, key, and user scopes; month and day windows) now admits a request only if spent + every OUTSTANDING in-flight hold + the request's cost UPPER BOUND fits the limit, and holds the bound until settle — so N concurrent near-cap requests can no longer all pass on the same remaining balance, and a bound exceeding the balance denies BEFORE egress (402, no provider request issued). The bound is estimated input plus the request's own `max_tokens` of output at the first resolved target's rate (unpriced ⇒ 0, degrading to the previous spent-only check; the ADR-030 guard owns that case). A deny after some windows already reserved rolls those holds back; a hold leaked by a crash between the phases self-heals at a 15-minute TTL; `warn` windows keep their exact previous meaning (they never deny, so they never hold). Settle releases the hold and debits actuals, freeing headroom immediately.
- **Demand-following rate shares** (ADR-043 second half): the per-plane rate split now follows real traffic instead of dividing equally. Each data plane counts settled requests and total tokens per team (denied requests earn no share), differentiates the counters per heartbeat, EWMA-smooths, and reports per-minute flow (`SyncRequest.flows`, additive); the control plane reserves half of each team rate rule's rpm/tpm as an equal floor — an idle plane can always start working without waiting a rebalance — and divides the other half proportionally to reported flow. Σ shares ≤ the configured limit by construction; a fleet with no flow reports (older builds, cold start) degrades to exactly the equal-split behavior. An unevenly loaded fleet no longer 429s early on its hot plane while cold planes sit on unused share.
- **Control-plane-owned budget window epochs** (roadmap ② second half): the control plane now computes each budget rule's window id (`"2026-09"` for CalendarMonth, `"2026-09-02"` for CalendarDay, UTC), rolls the lease ledger WHOLESALE when the epoch changes (a deliberate clock-driven reset, no longer a heuristic inferred from a decreasing counter), stamps every lease grant with the epoch, and refuses consumption reports stamped with a previous epoch — so a lagging data plane can never book an old window's spend into the fresh one, and every data plane observes ONE fleet-wide window boundary. mayu bridges the UTC-window vs `budget_timezone` phase difference by baselining its local counter at each observed epoch change (reports send counter−baseline; the lease clamp allows allowance+baseline). The ADR-041 tier latch now keys on the real epoch, and durable-ledger rows persist it so a restart never resurrects a rolled-over window's spend. Both wire fields are additive: a mixed fleet degrades to exactly the pre-epoch decrease-detection behavior.
- **Mutation evidence on mayu-plane management writes** (Phase 0b-4, completing the control-plane half): team upserts/deletes and provider/model writes/deletes now carry a `mutation` ref INSIDE the hash-chained audit record — the actor's durable identity (`issuer#sub`; empty for break-glass, never fabricated), the capability the route class required, and before/after sha256 of the canonical STORED row (read back from the store after the write, never hashed from the request body; an empty digest is an absence, not the hash of the empty string; digest inputs are secret-free by construction since team records and provider rows hold refs only). Appended at the audit Record's end (omitempty) so pre-existing chains verify byte-identically. With this, a management mutation on either plane is attestable — actor, scope, and exactly what changed — not just observable.
- **PII egress ceiling** (strategy Phase 2 v1): a GovernancePolicy `pii: {egress}` rule attaches a per-subject egress ceiling — `blocked` (refuse every generation request), `internal-only` (the resolved chain, fallbacks and substitutions included, is filtered to providers explicitly labeled `classification: internal`; unlabeled providers are external by the D7 rule), `external-masked` (refused fail-closed when the ADR-009 masking filter is not active for the team), and `external-unmodified` (egresses VERBATIM only after a completed detector pass — the typed `filter.Detection` result of the same Mask pass, run detect-only — reports nothing protected; no configured detector, a detector error, or a detector hit all refuse; the OpenAI ingress refuses it outright in v1, the same no-maskBody posture as its masked-team rejection). Ceilings fold most-restrictive across matching team/user rules. New audit deny codes `pii_blocked`, `pii_no_internal_target`, `pii_mask_unavailable`, `pii_detector_unavailable`, `pii_protected_detected`.
- **Two-pool user budget** (strategy Phase 1, [design spec](docs/specs/2026-09-02-two-pool-user-budget.md)): a user-subject budget rule may carve a `premium` pool out of its limit — `premium: {limitMilliUSD, models, fallback}`. Spend on premium-set models debits both pools; once the premium pool is exhausted, a premium request is served by the FIRST entry of the admin-approved fallback set that passes the caller's RBAC and is routed on the serving data plane (disclosed via `x-inferplane-substituted-model` and the audit record), and DENIED (402) when none is compatible — the premium model is never served past the pool. The total limit stays the ADR-042 hard cap (deny before egress). `GET /v1/usage` gains `user_premium`. v1 scope: CalendarMonth rules; per-data-plane counters (the ADR-042 accepted limitation).
- **Guardrail/residency coverage is now structural**: a fence test iterates every Bedrock egress path (`egressAPIs`) proving each either applies the effective guardrail on the upstream call or refuses a guarded request before egress — the Mantle refusal (no guardrail parameter on that endpoint) is now the documented permanent posture, so a guarded team can never be served unguarded while the audit chain attests otherwise. The Bedrock INGRESS also gained the per-team region-lock and guardrail-override wire tests the Anthropic and OpenAI ingresses already carried.
- **Control-plane policy-write gating + mutation audit** (Phase 0b-4): `INFERPLANED_OIDC_ROLE_MAPPINGS` (JSON groups→roles, typo-rejected at boot) requires `policy-admin` for `PUT`/`DELETE /v1alpha1/policies` when configured — the static token remains platform-admin break-glass — and every policy mutation records an `admin_mutation` line (actor `issuer#sub` or `static-token`, capability, action, scope, before/after sha256 of the canonical document, resulting generation) to `INFERPLANED_MUTATION_LOG` (append-only JSONL) or the process log, so a policy change is never silent. Closes ADR-038's accepted no-write-authorization/no-mutation-audit limitation.
- **Duty-separation admin roles** (Phase 0b-3, mayu admin plane): opt-in `oidc.role_mappings` maps IdP groups to a fixed role set (`platform-admin`, `policy-admin`, `provider-admin`, `budget-admin`, `auditor`, `team-admin` — typos rejected at config load), and each management route class (keys, teams, provider writes+probe, audit/logs/bodies reads, debug) requires a matching capability; denials are audited 403s naming the capability. Unconfigured deployments are byte-identical; the static admin token remains platform-admin break-glass. LiteLLM paywalls RBAC at its ~$30k/yr Enterprise tier.
- **Durable user identity** (Phase 0b-1/0b-2, [design spec](docs/specs/2026-09-02-durable-identity-and-management-authz.md)): a person's identity is now the canonical `UserID = issuer + "#" + subject` from the VERIFIED OIDC token, not a free-form owner string. Captured at CLI login (`mayu login` keys) and admin issuance (`keys.user_id` column, ALTER-migrated; non-admin callers always get their own verified identity; full admins may provision for others; `mayu keys create --user-id` and declarative `virtual_keys[].user_id` for service provisioning). Per-user budget enforcement, usage attribution, and the audit record (`principal.user_id`) all key on it — so key rotation, re-login, and a second device keep ONE budget ledger and ONE audit identity (e2e-proven), and an IdP migration can no longer collide two people on a bare `sub`. Owner remains as a display label and as a bounded fallback for pre-migration keys; a policy may still name the bare sub (matches any issuer, explicitly weaker).
- **Global rate limits via control-plane rate shares** (ADR-043): with a control plane attached, each team `rate` rule's rpm/tpm is divided among live data planes (equal split in v1, min-1 floor) and handed down in the heartbeat (`SyncResponse.rateShares`, additive), so the fleet aggregate stays at the configured limit instead of N× it — without a Redis dependency and without touching the request path. mayu clamps its locally-enforced rate to min(policy limit, share) — narrows-only, so a compromised control plane can only reduce throughput; failure semantics are FailOpen keep-last (an outage never widens back to the global limit, never zeroes). Verified by a two-gateway e2e: the 429 appears at the global limit. Per-key rates, token quotas, and standalone mode remain per-plane.
- **Durable lease ledger** (roadmap ② durability half): `INFERPLANED_LEDGER_PATH` (env-only, opt-in) persists the budget-lease ledger — per-(rule, dataplane) spent/allowance and data-plane liveness — to SQLite, write-behind on each heartbeat. An `inferplaned` restart resumes grants exactly, and a data plane that died before the restart keeps its spend on the books instead of the budget being re-granted as fresh money. Unset keeps the in-memory behavior byte-identical.
- **`mayu doctor` + `GET /admin/debug/governance`** (roadmap ④): one-command node-local diagnosis — config parse vs secret-ref resolution as separate checks, policy source, listen ports, pricing coverage, provider connection probes (`--no-probe` to skip real upstream calls), and control-plane reachability/apiVersion-overlap/token checks. Human output, `--json` for support tickets; secret ref names may appear, resolved values never. The admin plane additionally serves a secret-free governance snapshot (policy source, per-team usage, budget-lease windows, rate shares) behind the same AdminAuth as `/admin/config`, so an operator can pull the same picture remotely from a machine they can't shell into.
- **Fleet version visibility + update advice** (roadmap ③ phase 1): `mayu` embeds a build version (`-ldflags -X main.version`, Dockerfile `ARG VERSION`; new `mayu version` subcommand), reports it in every heartbeat, and `GET /v1alpha1/dataplanes` shows the fleet's version distribution. `INFERPLANED_MINIMUM_VERSION` (+ optional `INFERPLANED_UPDATE_URL`) sends `updateAdvice` to stale builds; mayu logs one loud warning per distinct advice. Advice only — the control plane can never push executable content.
- **Codex / OpenCode wire-shape fixtures**: the Chat Completions ingress is now pinned against both coding agents' documented request shapes — agentic function tools, the turn-2 tool-call round trip, and `stream_options.include_usage` — on both the verbatim (openai-wire) and Claude-translated (anthropic-wire) paths (`internal/server/openaiapi/agent_wire_test.go`).
- **Streaming overhead benchmark** (`benchmarks/streaming`): measures TTFT/inter-chunk/total for direct vs through-mayu (real binary, full governed hot path) vs a simulated central-gateway network hop. Illustrative loopback run: mayu +0.8ms TTFT p50 vs +17ms for a lossless 8ms-one-way central hop with zero processing modeled.
- **Competitive comparison** ([docs/comparison.md](docs/comparison.md)): dimension-by-dimension analysis vs LiteLLM and Portkey (security, cost control, cost accuracy, admin convenience, performance, model compatibility, authentication) for enterprise coding-agent traffic, every claim cited to code/ADRs or dated sources, with the consolidated close-the-gap list.
- **Budget-tier model substitution** (ADR-041): a `GovernancePolicy` `routing.budgetTiers` rule substitutes a cheaper, self-hosted target (e.g. Sonnet → GLM on vLLM) for designated requested-model names once a named team budget rule crosses an operator-set utilization threshold — judged GLOBALLY by the control plane from the ADR-034 lease ledger, latched per budget window so it never flaps request-to-request. Substitution is keyed by requested model name (never touches a long-conversation/main-loop model, which is simply left out of the map, so live prompt caches are never invalidated), can only narrow — never widen — access, and never turns into a denial: a target that fails RBAC or isn't routed leaves the original model served. Substituted requests advertise `x-inferplane-substituted-model`, the audit record's `model_substituted_from` carries the client's original request, and `inferplane_model_substitution_total` counts it. New `internal/tier` package (`Table` + window-latched `Latch`); `routing.onAffinityConflict` (cache-affinity, still unenforceable) and `routing.budgetTiers` are now mutually-exclusive halves of the same rule kind.
- **`inferplane login` / `token` / `logout`** (ADR-028): OIDC login for humans — trades an IdP session for an automatically-renewing, short-lived gateway virtual key instead of a hand-copied, never-expiring one. New opt-in data-plane endpoints `GET /v1/auth/config`, `POST /v1/auth/key`, `DELETE /v1/auth/key`; a second, distinct OIDC client from the admin console's; no IdP refresh token is ever cached on disk. CI/service-account provisioning (`inferplane keys create`, declarative `virtual_keys`) is unchanged.
- **Model-level fallback** (ADR-029): a hardcoded client requesting a not-yet-configured model (e.g. a new Claude release) is now served a configured model instead of 404ing, via config `model_fallbacks` or — with no config at all — a default same-family heuristic (`claude-opus-5` → the highest configured `claude-opus-*` version below it). A configured model whose upstream rejects it as unknown (404, or Bedrock `ValidationException`) also crosses to its fallback model within the existing priority-fallback chain. Substitution is fail-closed on RBAC (a key allowed only the requested name is denied, never silently downgraded) and advertised via `x-inferplane-model-fallback`.

### Fixed
- **Param strips are now disclosed per request** (strategy P1 "undisclosed request mutation"): when Bedrock's strip tables drop a sampling param a model rejects (e.g. `temperature` for gpt-5.6/xai targets), the response carries `x-inferplane-params-stripped` and the audit record carries `params_stripped` — previously the only signal was a once-per-process log line. The strip tables themselves are now pinned to a recorded probe artifact (`providers/bedrock/testdata/strip_tables.json`) by a CI guard, so a table drift is always an explicit reviewable diff.
- **A 2xx the gateway cannot account is now refused at every ingress** (strategy Phase 0a): a provider response with status < 400 but no parsed canonical body used to be served verbatim with zero settle, zero cost, and empty audit usage — the ADR-030 zero-cost class, which the Mantle path had already re-opened once (fixed provider-side). All three ingresses now fail closed on the non-streaming path: fall back to the next target when one exists, else a synthesized 502 — never an unbilled success. Fence tests per ingress keep a future egress from re-opening the class.
- **Cost settlement was wrong in five independent ways, producing 0 µUSD on real traffic** (ADR-030). Streaming requests billed **output tokens only** — input and prompt-cache counts arrive on `message_start`, which the settlement path never read (measured: 5 µUSD where 52 was correct, a 10.4x under-bill, and Claude Code traffic is effectively all streaming). Cache writes always billed at the cheaper 5-minute tier, leaving the 1-hour tier (2x input) unreachable. A config declaring only `input_per_mtok`/`output_per_mtok` billed **all cache tokens at zero** — cache rates are now derived from the input rate (0.1x / 1.25x / 2x, verified against both Anthropic's and Bedrock's published tables). Bedrock cross-region prefixes (`global.`/`us.`/`apac.`) missed the rate table entirely, and Bedrock Converse dropped cache tokens while InvokeModel kept them. The OpenAI-compatible ingress billed cached prompt tokens at the full input rate (over-billing). A stream that broke mid-flight billed nothing for tokens already delivered.
- `pricing.on_missing: "block"` was dead config — it behaved identically to `allow`, so unpriced traffic an operator believed was refused was served free. It is now enforced at boot and at runtime, and an unrecognized value is a load error instead of silently meaning `allow`.
- A non-admin OIDC identity issuing a key via `POST /admin/keys` could set `owner` to any value, letting a teammate attribute a key to someone else; the server now always overrides `owner` to the caller's own verified subject.

### Changed
- **BREAKING (only when `pricing.on_missing` is `"block"`):** the gateway now refuses to boot if any configured route has no pricing rate, naming the routes. With the default `allow` it logs them loudly and continues. Migration: declare the missing rates under `pricing.overrides` (two numbers per model — cache rates derive), or set `on_missing` to `"allow"`.
- **BREAKING:** a `pricing.overrides` entry declaring `0` for both `input_per_mtok` and `output_per_mtok` is now a load error instead of a silently accepted zero rate. `0/0` used to read as "this model is free", which is exactly how unpriced traffic ended up billing nothing. Migration: declare the real rates, or add `"free": true` to the entry — the only way to assert a genuinely zero-cost model.
- Bedrock's `mantle` egress now REFUSES a request whose model has a Guardrail configured (provider default or per-team override) instead of serving it unguarded. Mantle has no guardrail parameter, and the audit record attests the configured guardrail regardless — a silent bypass was being recorded as compliant. Route guarded models via `converse`/`invoke_model`, or drop the guardrail for that model.
- `pricing.version` labels the rate table and lands in every audit record's `cost.pricing_version`, which was previously the hardcoded string `"bundled"` even for fully-overridden tables — a disputed invoice can now be pinned to the rates that produced it.

## [0.2.0] - 2026-06-14

### Added
- **Free OIDC SSO for the admin plane** (ADR-004): the gateway validates IdP ID tokens (Dex/Keycloak/Okta) against the issuer's JWKS and maps the `groups` claim to teams; the static admin token remains as break-glass. Resource-server-only — no redirect/session/cookie, no CSP change.
- **Config hot-reload** (ADR-006): `SIGHUP` re-reads config and atomically swaps the provider/model/pricing topology with no restart; governance counters, keystore, and audit chain persist; a bad config rolls back.
- **Provider visibility** (ADR-005): read-only `GET /admin/config` and a console **Providers** tab show wired providers, endpoints, auth modes, and model routing — never a secret value.
- **Console operator dashboard** (ADR-002): token-gated SPA with Overview, Virtual keys, Providers, Governance, and Quickstart tabs; data-free static assets behind a strict CSP.
- **Governance views + one-click audit verify** (ADR-003 #2): per-team quota-utilization gauge and cumulative budget spend, plus `GET /admin/audit/verify` (per-sink hash-chain check, complete-prefix tolerant of a live writer).
- **Chargeback report** (ADR-007): `inferplane report` aggregates settled µUSD by team (or resolved model) from the audit log to CSV — exact integer-micros money, no float drift.
- **Per-team admin authorization + admin-action audit** (ADR-004): OIDC team-members issue/revoke keys only for their teams; every admin mutation and denial is an audit event.

### Changed
- Admin key management, config view, and audit verify are unified behind a single `AdminAuth` accepting static tokens or OIDC ID tokens on one bearer header.

## [0.1.0]

### Added
- Anthropic Messages ingress (`/v1/messages`, `/v1/messages/count_tokens`, `/v1/models`) with verbatim, cache-safe body forwarding.
- OpenAI Chat Completions ingress (`/v1/chat/completions`, `/v1/models`) with canonical-schema conversion.
- Virtual keys (`ik_...`) with team RBAC and per-key allowed-model lists; SHA-256 hashed at rest, shown once.
- Two-phase governance: per-team rate limits (TPM/RPM), daily token quotas, and monthly USD budgets with `block`/`warn` policies.
- Integer-microUSD pricing with round-half-even and TTL-tiered prompt-cache rates; `on_missing: allow` for self-hosted chargeback.
- Tamper-evident audit log: per-instance SHA-256 hash chain, disk WAL (`buffer_then_block`), and the `inferplane audit verify` command.
- Providers: Anthropic direct, Amazon Bedrock (Claude via InvokeModel, others via Converse), and any OpenAI-compatible endpoint, with priority fallback and per-provider circuit breakers.
- Prometheus `/metrics` on the admin plane using OpenTelemetry GenAI semantic conventions, plus a 9-panel Grafana dashboard.
- Optional self-terminated TLS on the data plane for non-Kubernetes deployments.
- Packaging: multi-stage `CGO_ENABLED=0` static Docker image (distroless/nonroot) and a Helm chart (ConfigMap config, IRSA ServiceAccount, `existingSecret` reference).

### Security
- Config rejects inline secrets; credentials are referenced only via `env:`/`file:`/`secret:`.
- The gateway never forwards the client key upstream and never exposes its upstream keys to clients.
- `/metrics` carries no secret or `key_id`, and bounds label cardinality with a `_rejected` sentinel on pre-resolution 403/404 paths.
- `count_tokens` always returns 200 to avoid crashing Claude Code.
