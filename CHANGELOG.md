## [Unreleased]

### Security
- **Go 1.26.10 toolchain.** Raise the minimum Go version and both Docker builders to include the `crypto/x509` certificate-distrust fix reported by CI as GO-2026-6809.
- **Native Responses routes forwarded stored-state references to the shared upstream credential.** `POST /v1/responses` passed `previous_response_id`, `conversation` and `item_reference` input items straight to `openai_responses` / `bedrock_responses` targets, which resolve them under the gateway's single upstream identity. A caller who learned another user's response, conversation or item ID could continue that user's provider-held conversation; the bridge already refused these fields, and teams with a privacy rule failed closed only because the request was uninspectable. Every Responses target now refuses them with 400 `stored_reference_unsupported` before routing, without echoing the ID. `store` and `background` are unchanged: no retrieval endpoint is mounted, so stored responses are unreachable through the gateway. Clients that relied on server-side state must resend the full input; per-user ownership binding is planned separately (Bedrock native parity plan, PR-12).

### Added
- **Native Bedrock Converse and local evaluation (ADR-052).** Converse/ConverseStream preserve native JSON/eventstream semantics with gateway signing, guardrail conflict checks and qualified usage settlement. Evaluation drives the same admission and audit gates. / **네이티브 Bedrock Converse·로컬 평가:** 서명·가드레일 검사·사용량 정산·감사 admission을 실제 요청과 동일하게 적용.
- **Atomic control-plane policy import.** Postgres policy-store deployments support authenticated all-or-nothing import with writer authorization and rollback on rejection. / **제어 영역 정책 일괄 가져오기:** 전용 쓰기 인증과 거부 시 롤백을 적용하는 원자적 가져오기 지원.
- **Strict config validation.** Unknown typed config keys refuse loading; `mayu config validate --config <path>` checks supported settings without opening stores/providers. / **엄격한 설정 검증:** 알 수 없는 키 거부 및 저장소·공급자를 열지 않는 검증 명령 추가.
- **Claude Sonnet 5.5.** The bundled rate table adds `anthropic-direct` / `claude-sonnet-5-5` at $2 input / $10 output / $0.10 cache read / $2.50 (5m) and $4 (1h) cache write per MTok: Sonnet 5 prices except cache reads, which are 0.05x input as for Opus 5.5. The console catalog lists `claude-sonnet-5-5` and `anthropic.claude-sonnet-5-5`. New `examples/config.bedrock-sonnet-5-5.json` routes `global.anthropic.claude-sonnet-5-5` through InvokeModel with exact Standard Global Seoul prices (AWS Price List published 2026-10-12) and fail-closed pricing; `us.anthropic.claude-sonnet-5-5` in us-east-1 needs its own prices. The existing `sonnet-5` legacy-thinking pattern already covers Sonnet 5.5, now pinned by a test. Known limits: `thinking.type: disabled` (use `between_tools`) and forced `tool_choice` still pass through and return 400 upstream.
- **Opt-in PII classifiers with a Korean sample.** A new `pii_classification` block attaches up to four self-hosted `systemone` classifiers (Laya, strands-decider) to the existing `sensitiveData` rules. A classifier reads the whole retransmitted request, including system input, tool schemas and history. Enforce flags apply `onDetected`; Mask escalates to `onUninspectable`; abstain, timeout and errors fail closed, also next to another entry's flag; Shadow only records. A window the server reports as cut (laya-serve reads about 980 tokens per window) is never Clear; the `truncation` option says whether the server reports cuts (`reported`, the default) or refuses over-length input (`rejected`). A node-local, team-scoped, clear-only HMAC verdict cache keeps long sessions affordable and is cleared on every reload and UI topology write. `examples/pii-classifier-ko/` ships the sample as recipes only: config, policy, an opt-in Helm sidecar (`piiClassifier.laya`, which requires the operator's own image repository and digest), the training recipe, an offline CPU image recipe that bakes the operator's checkpoint in, and the card of the reference checkpoint. No weights or image are published. Known limits: evaluation covers synthetic sets and the public KDPII dialogues, not real gateway traffic (numbers in the recipe v4 entry under Changed); a CPU sidecar costs about 0.5 s per 1,000-character Korean window; names and attributes in different windows or turns are not read together; per-key limits do not bound classifier load, because classification precedes admission; no span masking; only the internal boundary is supported.
- **Claude Opus 5.5.** The bundled rate table adds `anthropic-direct` / `claude-opus-5-5` at $4 input / $20 output / $0.20 cache read / $5 (5m) and $8 (1h) cache write per MTok. Cache read is 0.05x input, not the derived 0.1x. The console catalog lists `claude-opus-5-5` and `anthropic.claude-opus-5-5`. New `examples/config.bedrock-opus-5-5.json` routes `global.anthropic.claude-opus-5-5` through InvokeModel with exact Standard Global Seoul prices (AWS Price List, checked 2026-09-23) and fail-closed pricing. The Bedrock legacy-thinking adapter now matches `opus-5`, which covers Opus 5 and Opus 5.5; both reject `budget_tokens`. Known limits: `thinking.type: disabled` and forced `tool_choice` (`any`/`tool`, including OpenAI `required`) still pass through and return 400 upstream.
- **Budget-tier model substitution** (ADR-041): a `GovernancePolicy` `routing.budgetTiers` rule substitutes a cheaper, self-hosted target (e.g. Sonnet → GLM on vLLM) for designated requested-model names once a named team budget rule crosses an operator-set utilization threshold — judged GLOBALLY by the control plane from the ADR-034 lease ledger, latched per budget window so it never flaps request-to-request. Substitution is keyed by requested model name (never touches a long-conversation/main-loop model, which is simply left out of the map, so live prompt caches are never invalidated), can only narrow — never widen — access, and never turns into a denial: a target that fails RBAC or isn't routed leaves the original model served. Substituted requests advertise `x-inferplane-substituted-model`, the audit record's `model_substituted_from` carries the client's original request, and `inferplane_model_substitution_total` counts it. New `internal/tier` package (`Table` + window-latched `Latch`); `routing.onAffinityConflict` (cache-affinity, still unenforceable) and `routing.budgetTiers` are now mutually-exclusive halves of the same rule kind.
- **`inferplane login` / `token` / `logout`** (ADR-028): OIDC login for humans — trades an IdP session for an automatically-renewing, short-lived gateway virtual key instead of a hand-copied, never-expiring one. New opt-in data-plane endpoints `GET /v1/auth/config`, `POST /v1/auth/key`, `DELETE /v1/auth/key`; a second, distinct OIDC client from the admin console's; no IdP refresh token is ever cached on disk. CI/service-account provisioning (`inferplane keys create`, declarative `virtual_keys`) is unchanged.
- **Model-level fallback** (ADR-029): a hardcoded client requesting a not-yet-configured model (e.g. a new Claude release) is now served a configured model instead of 404ing, via config `model_fallbacks` or — with no config at all — a default same-family heuristic (`claude-opus-5` → the highest configured `claude-opus-*` version below it). A configured model whose upstream rejects it as unknown (404, or Bedrock `ValidationException`) also crosses to its fallback model within the existing priority-fallback chain. Substitution is fail-closed on RBAC (a key allowed only the requested name is denied, never silently downgraded) and advertised via `x-inferplane-model-fallback`.

### Fixed
- **Local monetary admission (ADR-054).** Reserve applicable hard scopes per provider attempt; concurrent admission cannot reuse outstanding credit, soft switching meters cannot replace independent hard caps, and interrupted/missing/invalid usage retains uncertainty instead of proving zero cost. This is process-local enforcement, not fleet-global escrow. / **로컬 금액 admission:** 시도별 예약으로 동시 사용과 soft/hard 충돌 방지, 불완전 사용량의 금액 책임 유지. 프로세스 로컬 범위임.
- **Client recovery signals.** Bounded context-limit evidence survives Bedrock/OpenAI-compatible normalization and Responses SSE translation; stream usage options merge without removing client options. / **클라이언트 복구 신호:** 컨텍스트 초과 의미와 클라이언트 스트림 옵션 보존.
- **Audit pressure and recovery.** WAL failure or retained required-sink pressure closes new admission; startup preserves retained records without blind partial-fan-out replay. Repair retained evidence/storage before restart. / **감사 압력·복구:** WAL 오류·필수 sink 적체 시 새 요청 차단, 재시작 전 보존된 증거와 저장소 복구 필요.
- **Operator configuration.** Reject ineffective audit failure modes; reject unsupported quota declarations; Helm config checksums trigger rollout and chart guidance uses the `mayu` CLI. / **운영 설정:** 미구현 감사 모드·미지원 quota 거부, Helm 설정 체크섬 및 CLI 안내 정정.
- **Bedrock Converse dropped every hyphenated tool, so non-Claude models never received most MCP tools.** `parseTools` accepted only `^[a-zA-Z][a-zA-Z0-9_]*$`, but the ToolSpecification name pattern is `[a-zA-Z0-9_-]+`; MCP-qualified names such as `mcp__websearch__ttobak-web-search-tool___WebSearch` or any `mcp__plugin_aws-core_…` tool were silently removed. Claude Code's ToolSearch then kept selecting a tool the model never saw and looped (observed: 231 iterations on `global.openai.gpt-6-sol`). Hyphens are now forwarded (a live Converse call with a hyphenated name returned `tool_use` for that name, 2026-09-25); dots, colons and spaces are still dropped, and the Responses bridge forwards hyphenated names instead of digest-aliasing them. Forwarding them exposed a second bug: a tool without a description was sent as `description: ""`, which Bedrock rejects for the whole request (ValidationException, min length 1); the field is now omitted when empty. Provider-only change, zero core diff.
- **An OpenAI-ingress request routed to an Anthropic-wire provider was forwarded as OpenAI JSON.** `/v1/chat/completions` keeps the client's OpenAI bytes in `RawBody` (cache invariant) and the canonical form in `Parsed`; `providers/anthropic` and the Bedrock InvokeModel/Converse paths read only `RawBody`. Converse parsed the OpenAI body as Anthropic JSON and silently dropped every tool definition, the `tool_calls`/`tool` history and `max_completion_tokens` (they became plain text blocks with no `maxTokens`); InvokeModel and Anthropic-direct forwarded `max_completion_tokens` and `tools[].function` onto a wire that has no such fields. Both providers now re-render the canonical request for the openai ingress only — the anthropic ingress stays byte-verbatim, the caller's `RawBody` is never mutated (fallback to another provider still sees the original bytes), and `providers/anthropic` sets a default `Anthropic-Version` when the OpenAI client sent none. Mantle already rendered per route and is unchanged. Provider-only change, zero core diff.
- **MCP tool search broke privacy-policy teams on the second turn.** The request inspector treated `tool_search_tool_result` and `tool_reference` blocks as unknown content, so a request replaying tool-search history was uninspectable and a `sensitiveData` rule with `onUninspectable: Block` refused it with 403 (`sensitive_blocked`). Both shapes are now inspected (tool names and error text are still scanned; unknown result objects and extra members stay uninspectable), and masking preserves the references. Claude Code still disables tool search behind a custom `ANTHROPIC_BASE_URL`; set `ENABLE_TOOL_SEARCH=true` on the client. Verified live on 2026-09-24 through Bedrock InvokeModel, which needs no beta for tool search; Converse still drops the search tool.
- **An OpenAI-wire stream that ended without a `finish_reason` reached Anthropic-speaking clients with no `stop_reason` at all.** `message_delta` is the only Anthropic frame that carries one, and it was emitted only when the upstream sent a `finish_reason` (or a usage-only chunk) of its own — a vLLM/Mantle stream that simply ran to `[DONE]` jumped straight from `content_block_stop` to `message_stop`, leaving the client unable to distinguish a completed turn from a truncated one. `ReadChatSSE` now synthesizes a terminal `end_turn` delta in exactly that case; any upstream message-level frame still suppresses it, since a consumer may treat the first `message_delta` it sees as end-of-message.
- **`google.gemma-4-*` was unusable on Bedrock Mantle.** Route selection is per-vendor segment, which put every `google.*` model on the bare `/v1/chat/completions` route — but gemma-4 answers only on `/openai/v1/chat/completions` and 400s "isn't supported on this route" elsewhere (probed live 2026-09-02). It is now routed there as a per-model exception; `google.gemma-3-*` is unaffected.
- **Converse usage for the OpenAI gpt-5.6 family double-counted cached tokens.** Bedrock reports that family's `inputTokens` INCLUSIVE of the cache read/write counts (OpenAI `prompt_tokens` semantics — verified on live traffic 2026-08-29→31: input = cache_read + cache_write + Δ across 20+ consecutive requests), while the Anthropic wire requires the three counts disjoint. Passing the inclusive value through made clients (Claude Code) compute context usage at ~2x the real prompt — a 1M-context model looked nearly full after a few turns — and made settlement bill every cached token twice (full input rate on top of the cache-read/-write rates), the egress mirror of the OpenAI-ingress bug ADR-030 fixed in `usageFromOAI`. `usageWithCache` now subtracts the cache counts back out for the `converseInclusiveInputUsage` allow-list (clamped at 0, never over-billing); unlisted families pass through untouched — Claude on Converse reports disjoint counts (ADR-030) and other implicit-caching families are unverified.
- **Cost settlement was wrong in five independent ways, producing 0 µUSD on real traffic** (ADR-030). Streaming requests billed **output tokens only** — input and prompt-cache counts arrive on `message_start`, which the settlement path never read (measured: 5 µUSD where 52 was correct, a 10.4x under-bill, and Claude Code traffic is effectively all streaming). Cache writes always billed at the cheaper 5-minute tier, leaving the 1-hour tier (2x input) unreachable. A config declaring only `input_per_mtok`/`output_per_mtok` billed **all cache tokens at zero** — cache rates are now derived from the input rate (0.1x / 1.25x / 2x, verified against both Anthropic's and Bedrock's published tables). Bedrock cross-region prefixes (`global.`/`us.`/`apac.`) missed the rate table entirely, and Bedrock Converse dropped cache tokens while InvokeModel kept them. The OpenAI-compatible ingress billed cached prompt tokens at the full input rate (over-billing). A stream that broke mid-flight billed nothing for tokens already delivered.
- `pricing.on_missing: "block"` was dead config — it behaved identically to `allow`, so unpriced traffic an operator believed was refused was served free. It is now enforced at boot and at runtime, and an unrecognized value is a load error instead of silently meaning `allow`.
- A non-admin OIDC identity issuing a key via `POST /admin/keys` could set `owner` to any value, letting a teammate attribute a key to someone else; the server now always overrides `owner` to the caller's own verified subject.

### Changed
- **Inspection documentation.** Distinguish required JSON structure checks from opt-in privacy enforcement/classification/masking. Responses and native Converse currently run finite PII detection during unconditional inspection; separating that cost is planned, not implemented. / **검사 문서:** 필수 구조 검사와 선택적 개인정보 기능 구분, Responses·네이티브 Converse의 상시 탐지 비용 및 분리 계획 명시.
- **Responses failure codes (ADR-053).** Gateway stream failures detected before SSE headers are committed now include a bounded `error.code` such as `upstream_timeout` or `stream_incomplete`, while retaining the existing `error.type="upstream_error"`. The recovery codes `context_length_exceeded` and `invalid_encrypted_content` retain `invalid_request_error`. Clients can use the added codes for more specific diagnostics; a code alone does not trigger request replay.
- **Korean PII sample: recipe v4 and reference revision `laya-ko-pii-v4s2`.** The example config and Helm values now name `laya-ko-pii-v4s2`; Shadow evidence gathered under `laya-ko-pii-v3s1` does not carry over. The recipe adds slot templates with direct identifiers and no name, short conversational texts, obfuscated values (fullwidth digits, spaced characters, Korean digit words) and KDPII (CC BY 4.0, attributed in the sample's NOTICE), split by dialogue so test dialogues are never trained on and capped at half of the training rows. A seed is selected on KDPII val F1 before six gates run once on test, the independent set and 18 fixed probes (`eval/probes.py`). KDPII test sentences, audit disputes excluded (`research/pii-finetune/results/kdpii/groups_v3s1.json`, `groups_v4.json`): recall 0.661 → 0.988, FPR 0.034 → 0.001, recall on direct identifiers without a name 0.638 → 0.997. Independent set v3 (`research/pii-finetune/results/indep/metrics_v3set.json`): F1 0.953 → 0.962, recall 0.953 → 0.986, FPR 0.036 → 0.048. The KDPII numbers are in-distribution. v4 flags more one-sided rule-B documents (14.5% → 20.6%) and lookalike-only documents (0.4% → 2.0%), and it flags a shop's or an office's landline, which the label policy cannot tell apart from a person's. No weights or image are published.
- **Build requirement: Go 1.26.9+.** Upgrade OpenTelemetry to 1.45.0, `golang.org/x/net` to 0.60.0 and its required `x/text` to 0.42.0 to address the export-configuration logging and HTTP/2/Precis vulnerabilities detected by CI. Both Docker builders use Go 1.26.9.
- **Helm chart: audit to stdout, no local growth, measured resources.** The default chart now configures an audit WAL with a single `stdout` sink and disables the local analytics index, so nothing grows on the pod volume; previously it shipped no audit sink at all. `examples/otel-collector/audit-filelog.yaml` collects the records off the node with a `filelog` receiver and exports each body verbatim to S3 (verified with otelcol-contrib 0.119.0: 41 records byte-identical, `mayu audit verify` OK; the S3 upload itself was not exercised). stdout is a best-effort sink, so size kubelet log rotation for collector outages. Default `resources` are now `requests: {cpu: 50m, memory: 64Mi}`, `limits: {memory: 256Mi}` with no CPU limit, from a 2026-09-25 measurement (27 MB idle, 79 MB peak above 1,000 req/s, 0.8–8.5 ms CPU per request).
- **BREAKING (only when `pricing.on_missing` is `"block"`):** the gateway now refuses to boot if any configured route has no pricing rate, naming the routes. With the default `allow` it logs them loudly and continues. Migration: declare the missing rates under `pricing.overrides` (two numbers per model — cache rates derive), or set `on_missing` to `"allow"`.
- **BREAKING:** a `pricing.overrides` entry declaring `0` for both `input_per_mtok` and `output_per_mtok` is now a load error instead of a silently accepted zero rate. `0/0` used to read as "this model is free", which is exactly how unpriced traffic ended up billing nothing. Migration: declare the real rates, or add `"free": true` to the entry — the only way to assert a genuinely zero-cost model.
- Bedrock's `mantle` egress now REFUSES a request whose model has a Guardrail configured (provider default or per-team override) instead of serving it unguarded. Mantle has no guardrail parameter, and the audit record attests the configured guardrail regardless — a silent bypass was being recorded as compliant. Route guarded models via `converse`/`invoke_model`, or drop the guardrail for that model.
- `pricing.version` labels the rate table and lands in every audit record's `cost.pricing_version`, which was previously the hardcoded string `"bundled"` even for fully-overridden tables — a disputed invoice can now be pinned to the rates that produced it.

## [0.2.0] - 2026-06-14

### Added
- **Free OIDC SSO for the admin plane** (ADR-004): the gateway validates IdP ID tokens (Dex/Keycloak/Okta) against the issuer's JWKS and maps the `groups` claim to teams; the static admin token remains as break-glass. Resource-server-only — no redirect/session/cookie, no CSP change.
- **Config hot-reload** (ADR-006): `SIGHUP` re-reads config and atomically swaps the provider/model/pricing topology with no restart; governance counters, keystore, and audit chain persist; a bad config rolls back.
- **Provider visibility** (ADR-005): read-only `GET /admin/config` and a console **Providers** tab show wired providers, endpoints, auth modes, and model routing — never a secret value.
- **Console operator dashboard** (ADR-002): token-gated SPA with Overview, Virtual keys, Providers, Governance, and Quickstart tabs; data-free static assets behind a strict CSP.
- **Governance views + one-click audit verify** (ADR-003 #2): per-team quota-utilization gauge and cumulative budget spend, plus `GET /admin/audit/verify` (per-sink hash-chain check, complete-prefix tolerant of a live writer).
- **Chargeback report** (ADR-007): `inferplane report` aggregates settled µUSD by team (or resolved model) from the audit log to CSV — exact integer-micros money, no float drift.
- **Per-team admin authorization + admin-action audit** (ADR-004): OIDC team-members issue/revoke keys only for their teams; every admin mutation and denial is an audit event.

### Changed
- Admin key management, config view, and audit verify are unified behind a single `AdminAuth` accepting static tokens or OIDC ID tokens on one bearer header.

## [0.1.0]

### Added
- Anthropic Messages ingress (`/v1/messages`, `/v1/messages/count_tokens`, `/v1/models`) with verbatim, cache-safe body forwarding.
- OpenAI Chat Completions ingress (`/v1/chat/completions`, `/v1/models`) with canonical-schema conversion.
- Virtual keys (`ik_...`) with team RBAC and per-key allowed-model lists; SHA-256 hashed at rest, shown once.
- Two-phase governance: per-team rate limits (TPM/RPM), daily token quotas, and monthly USD budgets with `block`/`warn` policies.
- Integer-microUSD pricing with round-half-even and TTL-tiered prompt-cache rates; `on_missing: allow` for self-hosted chargeback.
- Tamper-evident audit log: per-instance SHA-256 hash chain, disk WAL (`buffer_then_block`), and the `inferplane audit verify` command.
- Providers: Anthropic direct, Amazon Bedrock (Claude via InvokeModel, others via Converse), and any OpenAI-compatible endpoint, with priority fallback and per-provider circuit breakers.
- Prometheus `/metrics` on the admin plane using OpenTelemetry GenAI semantic conventions, plus a 9-panel Grafana dashboard.
- Optional self-terminated TLS on the data plane for non-Kubernetes deployments.
- Packaging: multi-stage `CGO_ENABLED=0` static Docker image (distroless/nonroot) and a Helm chart (ConfigMap config, IRSA ServiceAccount, `existingSecret` reference).

### Security
- Config rejects inline secrets; credentials are referenced only via `env:`/`file:`/`secret:`.
- The gateway never forwards the client key upstream and never exposes its upstream keys to clients.
- `/metrics` carries no secret or `key_id`, and bounds label cardinality with a `_rejected` sentinel on pre-resolution 403/404 paths.
- `count_tokens` always returns 200 to avoid crashing Claude Code.
