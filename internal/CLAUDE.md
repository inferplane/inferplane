# internal Module

## Role
Private gateway internals — everything that is not a provider or a public package.
Packages are leaf-oriented to avoid import cycles (`principal`, `metrics`, `governance`
are leaves that others depend on).

## Invariants
These are the facts in this module worth knowing before touching it — the rest is
in the code and in `docs/decisions/`.

- **Pre-check before billing, settle after.** `on_exceeded` block wins on tie (`governance/`).
- **Cost is integer microUSD, never float.** Round-half-even via `math/big`.
- **`count_tokens` must never return non-200.**
- **Money units cross a boundary exactly once:** wire policy documents are milliUSD
  (1000 = $1, operator-facing); `policy/` converts to internal µUSD (×1000, exact) and
  nothing downstream re-converts. Settling coarser reopens ADR-030's zero-cost bug class.
- **Secrets never enter a DB-backed store** (`providerstore/`, `policystore/`) — only refs.
  A `policystore` constructor error is a hand-written string that never wraps the
  underlying pgx error, which can embed the DSN (and a password).
- **`key_id` never reaches a `/metrics` label**, but may reach a webhook payload body
  (`alert/`) — a label is cardinality-unbounded exposure, a payload body is not.
- **A raw user id never reaches a `/metrics` label** (`keystore.Principal.Owner`, an
  admin-supplied free string or an OIDC `sub`) — the same unbounded-cardinality bar
  `key_id` sits behind: no user-labelled series, no `SetBudgetUtilization` user
  variant, and no `alert/` dedup map keyed on a raw user id (`fired`/`firedKey` are
  unbounded in-memory maps; a `firedUser` would be a leak). A webhook payload body
  MAY carry one (`Fire.KeyID` is the precedent) — the restriction is metric
  cardinality and unbounded dedup maps, not exposure.
- Keep `principal`, `metrics`, `governance` import-cycle-free — widely depended on.
- Metric labels are config-bounded; never label with raw client input (`_rejected`
  sentinel on pre-resolution rejects).
- A policy from `policy/`/`policystore/` can only **narrow** a key's allow-list or
  budget, never widen one already set elsewhere (`router.SetPolicyGate`).
- PII egress ceilings (strategy Phase 2 v1) are enforced on the RESOLVED chain at
  the same point as the region lock, in every ingress: `Store.EgressCeiling`
  folds `pii: {egress}` rules most-restrictive (blocked > internal-only >
  external-masked > external-unmodified); `router.FilterInternal` keeps only
  providers explicitly `classification: "internal"` (unlabeled = external,
  the D7 fail-closed rule); an `external-masked` ceiling on a team without
  an active ADR-009 mask refuses — a mandated mask that cannot run never
  goes external. `external-unmodified` egresses VERBATIM only after a
  completed detector pass reports nothing protected: the detector is the
  SAME `maskBody` pass masking uses, run detect-only into the typed
  `filter.Detection` result, so detection and transformation can never
  disagree; no configured detector, a detector error, or a hit all refuse
  (`pii_detector_unavailable` / `pii_protected_detected`), and the OpenAI
  ingress refuses it outright in v1 (no `maskBody` there — the same posture
  as its masked-team rejection). Detector EVIDENCE rides the audit chain:
  masked requests and unmodified-refusals carry `Record.PII`
  (`{redactions, kinds}` — filter-declared kind names via the optional
  `filter.KindReporter` capability, counts only, never a matched value),
  threaded by `audit.WithPIIDetection` context plumbing from
  `maskBodyDetail` (the Detection-returning core `maskBody` now wraps).
- RBAC re-check after routing: `router.FilterModelAllowed`/`FilterRegions` must run
  right after `ResolveChain` in every ingress handler — the router has no `Principal`
  in scope, so a model-fallback or region-filtered target appended *after* the
  original allow-list check is not itself RBAC-checked until the handler does it.

## Key Packages
- `server/` — HTTP data plane + admin plane. Ingress handlers: `anthropicapi/`, `openaiapi/`, `bedrockapi/` (ADR-024); `responsesapi/` serves `POST /v1/responses` (the wire current Codex requires) as an ADAPTER over the chat ingress — translate to the chat wire, serve through the SAME pipeline (auth/RBAC/governance/PII/audit — records carry ingress "openai", the serving pipeline), translate the JSON/SSE back (tool-call deltas reassembled; item lifecycle events before text deltas or Codex logs protocol errors); untranslatable params are dropped WITH disclosure (`x-inferplane-responses-params-dropped`), and its test fixture is Codex 0.152.1's real captured request; `embeddingsapi/` serves `POST /v1/embeddings` (roadmap ⑤) as a governed PASSTHROUGH over the optional `providers.Embedder` capability — embeddings don't fit the canonical schema, so the body forwards verbatim (provider rewrites only the top-level model) while RBAC + post-routing re-check, region lock, PII ceiling (blocked/internal-only enforced; masked/unmodified refuse — no masker/detector on this lane), PreCheck with cost reservation (input-only upper bound), priority fallback over Embedder targets, Settle on `usage.prompt_tokens`, and the zero-bill fence (2xx without usage refused) all apply; `usageapi/` self-service `GET /v1/usage` (ADR-021); `authapi/` opt-in CLI login (ADR-028); `adminapi/`, `configapi/`, `auditapi/`, `analyticsapi/`; `debugapi/` serves `GET /admin/debug/governance` (roadmap ④ remote half — policy source, per-team usage/leases/shares; TEAM-subject usage only so it stays key- and user-free, same AdminAuth + secret-free bar as `/admin/config`, nil closure = route not mounted); `adminui/` embedded console (ADR-001, SSO ADR-026, i18n ADR-027). A mid-stream upstream failure surfaces as a wire-appropriate error frame (SSE `error` event / eventstream exception), never a silent truncation, and the audit record is marked `partial: true`. **A 2xx the gateway cannot account is refused (Phase 0a fence):** every ingress's non-streaming path fails closed on `StatusCode < 400 && Parsed == nil` — fall back if a target remains, else a synthesized 502 — because serving it would bill 0 µUSD with empty audit usage (the ADR-030 class; `zero_bill_fence_test.go` in each ingress package pins it). Consequence for test stubs: a fake provider returning a 2xx must set `Parsed`, like every real provider does. **Every observability sink sees the same settled usage.** A partial stream's usage is settled, so it must also be `observeTokens`'d — metering only the clean path left `gen_ai_client_token_usage_total` below the budget spend, the audit ledger, and the usage windows on every interrupted stream. `recordSpanSettled` (not `recordSpanResponse`) is the span call at the three COMMITTED sites; `recordSpanResponse` stays for the terminal pre-commit rejects, where there is no usage or cost to report.
- `router/` — model→provider resolution (`ResolveChain`), priority fallback, per-provider circuit breaker. `Canonical`/`Allows` (ADR-021) canonicalize model aliases before RBAC. `ResolveModel` (ADR-029) substitutes an unrouted model via `model_fallbacks` or same-family default before the allow-list check. `FilterRegions`/`FilterModelAllowed` are the pure RBAC re-check functions ingress handlers must call after `ResolveChain` (see Invariants). `SetPolicyGate` (ADR-033) ANDs an optional GovernancePolicy check onto every `Allows` decision. `SetTierGate`/`SubstituteTier` (ADR-041) substitute an ALREADY-routed model per an active budget tier — a distinct call from `ResolveModel`, since that method's contract ("a configured model is never second-guessed") and its lack of a `Principal` are both wrong for a cost-triggered, RBAC-checked substitution; fires only when the original passes `Allows` and only if the target also does, so it can never widen access or turn into a denial.
- `governance/` — `Governor` (`PreCheck`/`Settle`). `SetLeaseGate` (ADR-034) checks a budget lease first in `PreCheck`, denying 402 before any counter is charged. `UsageOf` (ADR-021) is the read-only companion behind `GET /v1/usage` — no debit, no state change. `SetTeamLookup` (ADR-016) prefers a DB team record over the static config map. `SetBudgetNotify`/`SetKeyBudgetNotify` (ADR-017) fire post-debit alert hooks. `Settle` takes the exact estimate `PreCheck` charged and trues up TPM against actual usage via `AdjustRate` (ADR-039), and debits the daily quota by total tokens including all three cache tiers — not `Input+Output` alone. `PreCheckCost`/`SettleCost` (strategy Phase 1 reserve/settle) are the cost-aware variants every ingress calls: the request's cost UPPER BOUND (`governance.CostUpperBound` — estimated input + the request's own max_tokens of output at the FIRST target's rate; unpriced = 0, plain checks) is HELD on every block-posture budget window between the two calls, so concurrent near-cap requests cannot pass on one remaining balance; a deny mid-PreCheck rolls earlier holds back (`resTracker`), `SettleCost` releases via `releaseReservations` (which mirrors the reserving conditions exactly), warn windows never hold, and the ingress passes ONE estCost variable to both calls so hold and release always match — a mismatch (or a request that never settles) leaks only until `reserveTTL` (15m). `PreCheck`/`Settle` also enforce a calendar-DAY budget beside the monthly one, against a separate counter with its own store key, block wins on tie via whichever window resets soonest; `SetBudgetTimezone` is the `budget_timezone` seam (nil = UTC) and now anchors BOTH calendar windows — the month boundary honours the operator timezone too (ADR-042), no longer the day's midnight only. `PreCheck`/`Settle`/`UsageOf` take a `Subject{Team, KeyID, User}` value replacing the two leading string args (ADR-042 Phase 3) — each ingress builds it with its own `subjectOf`, same deliberate per-package duplication as `keyPolicyOf`, keeping this package a leaf. `SetUserLookup`/`UserPolicy` add per-USER budget: budget only (no RPM/TPM), ONE `on_exceeded` for both windows (block wins on tie, collapsed in the gateway closure). `UserPolicy.Premium*` + `Governor.PremiumExhausted` + the Settle premium debit are the Phase 1 two-pool half — governance only ACCOUNTS the pool (classification via `policy.PremiumMatch` on the SERVED model, so a fallback-served request never drains it); the fallback ladder itself is `router.ApplyUserPool`'s business (first compatible or BLOCKED — the deliberate asymmetry with `SubstituteTier`'s never-deny contract), gated per request by the gateway's `SetUserPoolGate` closure and called in each ingress right after the ADR-041 seam. The user counter's id is `team + "/" + user` (`userBudgetID` — "/" is safe because `adminapi.validateTeamName` forbids it in team names, so the split point is unambiguous); a user-ONLY subject therefore counts separately per team, accepted in ADR-042. `GET /v1/usage` gains `user_budget`/`user_budget_day` (appended, omitempty).
- `keystore/` — virtual-key `Store` (SQLite), `Principal`, RBAC `Allows()`. `TeamStore` (ADR-016) is the `teams` table (allow-list, RPM/TPM, budget, guardrail override ADR-019, region lock ADR-020). `KeyEnsurer.EnsureKey` (ADR-023) upserts a caller-supplied plaintext so a config-declared key survives a wiped store. `ErrKeyExpired` (ADR-028) is distinct from `ErrKeyNotFound` so an expired CLI-minted key gets a different 401 message — still 401 either way. `KeyOptions.UserID`/`keys.user_id` (Phase 0b-1, ALTER-migrated) is the durable identity `issuer#sub` from the VERIFIED token — CLI login and non-admin admin-issuance always bind the caller's own; Owner is a display label. Each ingress's `subjectOf` prefers UserID with a bounded Owner fallback (0b-2) and `identityOf` does the same for usage attribution, so a person's budget window and audit identity survive key rotation and a second device; the gateway user-lookup closure retries a policy's bare-sub name when the exact `iss#sub` lookup misses (explicitly weaker operator convenience, spec §3.3). Both `teams` and `keys` carry a `budget_usd_micros_per_day` column (calendar-day µUSD cap, 0 = unlimited; ALTER-migrated so pre-existing rows read back 0).
- `audit/` — single-writer hash-chain writer, WAL, `verify.go`. `audit/s3anchor/` is opt-in S3 Object Lock anchoring (ADR-012). `Record.BodyRef`/`RecordRef` (ADR-018) are appended at the struct end (omitempty) so mixed-version chains still verify byte-identically. `UsageRef.CacheCreation{5m,1h}InputTokens` follow that same append-at-the-end rule: `CacheCreationInputTokens` stays the flat TOTAL for existing consumers while the two tiers make the 1.25x/2x billing reproducible from the ledger alone. `RequestRef.ModelSubstitutedFrom` (ADR-041, appended at that struct's end, same rule) carries the client's ORIGINAL requested model when a budget tier substituted it — `ModelRequested` by then already holds the model actually served. `WithSubstitutedFrom`/`SubstitutedFrom` thread it via request context from the ingress substitution point down to the audit call. `RequestRef.ParamsStripped` (strategy P1 disclosure, appended after it, same rule) names the request params the PROVIDER dropped before egress (`providers.ProxyRequest.ParamsStripped`, the one provider-set upward field); `WithParamsStripped`/`ParamsStrippedFrom` thread it the same way, and each ingress also sets `x-inferplane-params-stripped` on the response — pr.ParamsStripped is reset per target attempt so a failed target's strips never leak into another target's disclosure. `Record.PII` (`PIIRef`, strategy Phase 2 detector evidence, appended at the Record END, same rule) carries `{redactions, kinds}` on masked requests and external-unmodified refusals — counts and filter-declared kind names only, never matched values, and map keys marshal sorted so the hash-chain bytes stay deterministic. `Record.Mutation` (`MutationRef`, Phase 0b-4, appended after that, same rule) is the what-changed evidence on admin-plane mutation events (team upsert/delete, provider/model write/delete): durable actor `issuer#sub` (empty for break-glass), capability, before/after sha256 of the canonical STORED row — read back from the store, never hashed from the request body; empty digest = absence, never the hash of the empty string (`audit.SHA256Hex`). The provider/model before/after images flow through the optional `configapi.Reader` seam (`cmd/mayu/gateway.go` implements it over the provider store); team images come from `TeamStore.GetTeam`.
- `bodystore/` — opt-in encrypted request/response body capture (ADR-018), OUTSIDE the audit chain. Envelope AEAD; `Fetch` is fail-closed (any decrypt/miss → 410 tombstone, never plaintext). SQLite/Postgres backends; key rotation via `bodies rewrap-key`.
- `analytics/` — derived usage read-model backing `GET /admin/logs`; `pgstore/` is the shared-Postgres backend (ADR-015).
- `pricing/` — integer microUSD table, round-half-even. **ADR-030**: rate key is `(config provider name, UPSTREAM model id)`, never the canonical ingress name — the single most common way to end up billing 0. `HasRate` backs both boot validation and the runtime guard, so they can't drift apart. Cache rates derive from the input rate (0.1x read / 1.25x 5m-write / 2x 1h-write) unless explicitly overridden. A `0/0` override without `"free": true` is unpriced, not free — the row is left out of the table entirely, so `HasRate` is false and every unpriced path engages; `free: true` is the ONLY way to declare a genuinely zero-cost model.
- `limiter/`, `budget/` — in-memory two-phase governance stores with injectable clocks. `LimiterStore.AdjustRate` (ADR-039) is a post-hoc balance correction on a token bucket, not a second refill — it never floors a debit at zero (a bucket driven negative stays blocked until real refill time repays it). Per-instance state (see ADR-013 in Design Debt below). `budget.Window`'s calendar kinds (`CalDay`/`CalMonth`) get separate counters via `budget.Key`'s tag-first layout (`budget:day:...` vs `budget:month:...`), which is what keeps the day and month windows from sharing a bucket. `CalendarMonthIn(loc)` mirrors `CalendarDayIn` so the month window honours `budget_timezone` too (ADR-042); `Tag()` ignores `Loc`, so switching the operator timezone moves a counter's boundary, never its store-key identity. `TryReserve`/`Release` (strategy Phase 1) are the reserve/settle half: an atomic check of spent + outstanding TTL'd holds + the estimate, holds fungible only by exact amount (Release matches amount; a mismatch leaks until TTL, never double-frees), Release never creates or rolls a counter (a rolled window killed its holds), and a plain `Check` still reads spent only so warn windows keep their meaning. `budget.Memory` is now bounded (ADR-042 Phase 3): an amortized expired-entry sweep every 256 `cur` calls (`sweepEvery`) plus a `maxEntries` fail-closed cap (`defaultMaxEntries` ~100k) — a refused NEW key makes `Check` return `Block`, never a silent `Allow`, and rolling an EXISTING key over its window boundary is never refused. `Rejections()` is the operator seam; deliberately no metric behind it (a user-dimensioned label is forbidden — see Invariants). `ScopeUser` is now used: the user budget counters (`budget:day:user:team/sub`) are its first consumer; `ScopeUserPremium` (`budget:month:userprem:team/sub`, Phase 1 two-pool) is the premium pool — SERVED-premium spend debits both it and the user total.
- `alert/` — budget-alert webhook emitter (ADR-017). Fire-and-forget JSON POST on each newly-crossed utilization threshold; per-team and per-key paths dedupe independently. (ADR-041 designs a `tier_activated`/`tier_deactivated` event on this same emitter; not yet wired — see roadmap.)
- `metrics/` — Prometheus registry + GenAI collectors + nil-safe hooks. `ObserveModelSubstitution` (ADR-041, `inferplane_model_substitution_total{team,from_model,to_model}`) is labeled only from policy-declared values, same cardinality posture as `ObserveFallback`.
- `tier/` — ADR-041 budget-tier model substitution primitives, shared by `controlplane/` (judges) and `proxy/`/`cmd/mayu` (applies). `Table` is the request-path per-team substitution map (`Get`/`Set`, mirrors `proxy.LeaseTable`'s shape); a cross-rule key conflict resolves to the higher `ThresholdPercent` (deeper budget pressure), ties broken by `(policy, rule)` name for determinism. `Latch` makes tier activation monotone within one budget window — it never de-escalates on a dip, only resets when its window key changes: on the control plane that key is now the referenced budget rule's REAL window epoch (`ruleLedger.windowID`, roadmap ② shipped); `WindowKey` (calendar-month-UTC) remains only for standalone mode's latch in `cmd/mayu`, which has no control plane to own an epoch. A leaf package: no import of router/server/governance, only `policy` for the wire `ActiveTier` shape.
- `openai/` — OpenAI ⇄ canonical conversion.
- `adminauth/` — admin-plane OIDC identity leaf (ADR-004): shared bearer-shape predicate, groups→team mapping, go-oidc verifier. `roles.go` (Phase 0b-3): the FIXED duty-separation role set (`ValidRole` — config rejects typos at load) + `ResolveRoles` from the same verified groups claim; `MappingConfig.RoleMappings` empty = gating off. `server.RequireCapability` enforces per route class inside AdminAuth (audited 403 naming the capability); an identity with roles but no team mapping authenticates under active gating (an auditor need not belong to a team); break-glass carries platform-admin explicitly.
- `live/` — reloadable topology (providers + routes + pricing) behind one atomic `Holder` (ADR-006). `BuildState` also runs pricing-coverage validation (ADR-030): `on_missing: block` refuses to boot on an unpriced route; `allow` (default) logs loudly and continues. `Canonical`/`FallbackFor` back the router's alias and model-fallback resolution. `BuildStateWith(cfg, Deps)` (ADR-040) is the injection seam the gateway uses to hand a `providers.CredentialSource` to provider construction; `BuildState(cfg)` is `BuildStateWith(cfg, Deps{})`. `Deps` is a pure pass-through — `live` must not gain dependencies of its own, and the structural import-guard test enforces that.
- `providerstore/` — opt-in DB-authoritative provider/model topology (ADR-008). Refs only, no secret column. UI writes build-once-swap-once under one `reloadMu`. `Target.Pricing` (ADR-041 item 6) is a route target's optional nominal per-MTok rate (USD floats; `free` per the ADR-030 rules — 0/0 without it is rejected at the write DTO, which is what lets SQLite reconstruct nil from all-zero columns): `PricingOverrides` folds targets into (provider, upstream)-keyed rates plus a conflicts list, and `OverlayFrom` merges the fold into the effective config's `pricing.overrides` copy-on-write with a DB rate winning over a file entry for the same key — so the table build, cache-rate derivation, unpriced guards, and `mayu pricing check` apply unchanged. A rate CONFLICT (two routes, same key, different rates) is rejected by `writeMutation` before persisting; the boot `Overlay` only logs it (a direct-DB-edit-only state — refusing to boot over it would be a new outage mode) and proceeds first-declaration-wins. The `/admin/config` view echoes the STORE-carried rate per target (`configapi.AttachStoredPricing` — never the effective/bundled rate: the console form round-trips what it echoes, so echoing a bundled rate would silently copy it into the store), and `/admin/config/export` carries DB-entered rates as a config-shaped `pricing.overrides` fragment (assembly-attached; the topology snapshot alone cannot know which rates were DB-carried).
- `config/` — config loading + secret-ref resolution (inline secrets rejected). OIDC block validation; `CLILogin` requires a client ID distinct from the console's own (ADR-028). `ModelFallbacks`/`ModelFallbackFamily` (ADR-029) validated at both the file-load and UI-write paths. A bedrock provider's `auth.mode` is a CLOSED set (ADR-040 fail-closed invariant #2 — before it, any unrecognized string silently meant "default", so a typo deployed the bypassable local-IAM posture); the check lives in `ResolveProviders` precisely because that is the one path BOTH the file load and the ADR-008 UI write go through. `auth.mode: "broker"` additionally requires a `control_plane` block, a `broker_token_ref` resolving to a value DIFFERENT from `token_ref`, and an https-or-loopback control-plane URL.
- `principal/` — request-scoped principal context (leaf, breaks import cycles).
- `tracing/` — opt-in OpenTelemetry seam (ADR-011): OTLP **trace** exporter + GenAI-semconv spans + W3C propagation + `trace_id` in audit. No-op by default. Traces are the ONLY OTLP signal — metrics are Prometheus exposition (`metrics/` is the one registry; a second OTLP metric SDK would double-instrument and drift) and logs are the audit chain, not OTLP. Attributes semconv has no name for take an `inferplane.` prefix, never an invented `gen_ai.*` one: `SetUsageDetail` (cache read / 5m / 1h write, zero tiers omitted), `SetCost` (integer µUSD + `pricing_missing`, always paired — a 0 with the flag is "unpriced", without it "free"), `SetPartial`. No secret, `key_id`, or raw client input ever reaches a span attribute.
- `filter/` — request-transform filter seam (ADR-009): `RequestFilter` interface + registry. Concrete filters live under `plugins/<name>/` and register via blank import.
- `policy/` — rule + budget-lease schema shared by BOTH binaries (ADR-031/032/033) — the single source of truth. Converts `api/v1alpha1` wire docs and explicitly rejects anything unsupported (`UnsupportedError`, reported upstream, never silently ignored). Subjects (`team`/`user`) are equal citizens; most-restrictive-wins on multi-match. Exactly one rule kind per rule; `failurePolicy` required, no default. A `rate`/`budget` rule may set `unlimited: true` instead of a numeric limit — an explicit, auditable "no cap" (ADR-039) that internally still produces the pre-existing zero-value sentinel every consumer treats as unlimited; `mergeTeamLimits` and the controlplane lease ledger both give it its own branch so it can never narrow, widen, or silently overwrite a real limit set by another rule. The local file channel (ADR-033) rejects the routing rule's cache-affinity half and user-subject rate rather than accepting and ignoring them; the routing rule's `budgetTiers` half (ADR-041) and user-subject BUDGET rules (ADR-042 Phase 3) ARE enforceable — `Routing` is exactly one of `Affinity` or `BudgetTiers`. `Store.SetRoutedAndPriced` installs the ADR-041 apply-time check that a substitution TARGET is routed+priced on this data plane (nil skips it; the control plane's `LoadWirePaths` deliberately never installs one, same posture as its skip of `checkEnforceable`). `BudgetRule.period` (ADR-042) selects a budget rule's calendar window — `CalendarDay` | `CalendarMonth`, empty = CalendarMonth, so every pre-existing document keeps its meaning; a day cap plus a month cap are TWO rules in one policy (`hardCap`/`failurePolicy`/`lease`/`adminContact` are per-rule, and so is the lease ledger row), and `period` must not be combined with `unlimited`. `TeamLimits` folds the day window independently of the month (`BudgetMicrosPerDay`/`BudgetDayHard`/`AdminContactDay`) — most-restrictive-wins is computed per window, and `unlimited` is window-agnostic, touching neither. `UserLimits`/`mergeUserLimits` (ADR-042 Phase 3) do the same for user-subject BUDGET rules — budget only, no RPM/TPM; most-restrictive-wins per window via `narrow`, `unlimited` window-agnostic here too — and `Store.UserLimits(team, user)` folds a user-only subject together with the (team, user) one. `checkEnforceable` is now rate-only for the subject restriction: user-subject budget is enforceable, user-subject rate still is not (needs a rate-share model).
- `policystore/` — opt-in Postgres-authoritative GovernancePolicy store for `inferplaned` (ADR-038). The document, not the rule, is the CRUD unit. File-loaded set = seed, DB = authoritative once seeded (marker-gated, never row-count).
- `controlplane/` — `inferplaned`'s distribution core (ADR-034): `POST /v1alpha1/sync` is one heartbeat (policy pull + consumption report + lease renewal + rejection report + ADR-041 active-tier judgment). Budget-lease ledger is in-memory; its rows carry the rule's budget `period` and each grant is stamped with it (ADR-042), so a day rule and a month rule lease independently — a grant or report without a period reads as CalendarMonth, the meaning the wire had before windows existed. `(*ruleLedger).totals` is the one Σspent/Σoutstanding computation the lease-grant loop and the ADR-041 tier judgment both call, so they can't compute utilization differently by accident. Window epochs (roadmap ② second half, shipped): the control plane OWNS the budget window — `windowIDFor(period, now)` computes a UTC calendar epoch id ("2026-09" / "2026-09-02"), `(*ruleLedger).roll` resets a rule's spend/allowance WHOLESALE when the id changes (every `handleSync` rolls all ledgers first), every grant is stamped `WindowID`, a report stamped with a previous epoch is refused (spend in a currency the ledger no longer holds), and the tier latch keys on the referenced budget rule's real epoch. The decrease-detection heuristic remains ONLY as the fallback for epoch-less reports from older builds; ledger-store rows persist the epoch and a stale-epoch row is skipped at load (`SetLedgerStore` rolls each ledger before restoring so a current-epoch row isn't wiped by the next heartbeat's roll). `tierLatch` (`*tier.Latch`) is a `Server` field, NOT rebuilt in `applyWire` — it must survive a policy edit the same way ledger spend/allowance does, or every reload would silently un-latch every team mid-window; only rules that no longer exist get their latch state forgotten. A USER-scoped budget rule gets NO ledger row and NO grant (`applyWire` skips it, ADR-042 Phase 3): the row is team-keyed and its clamp would throttle the whole team to one individual's limit — per-user budget is per-data-plane in-memory, same posture as `rate`. `applyWire` (ADR-038) is the one install path both the file loader and the DB loader go through, so ledger semantics never diverge by source. `policies.go` mounts read routes behind the shared auth; WRITES go through `authnCap` (Phase 0b-4): policy-admin required when `RoleMappings` are configured (static token = platform-admin break-glass; a role-holding identity with no group→access mapping still authenticates, the mayu-plane rule), and every PUT/DELETE records an `admin_mutation` (`mutationlog.go` — actor from the `Actor(ctx)` stamp, before/after sha256 of the canonical doc, generation; JSONL sink via `SetMutationLog`, process-log fallback so a mutation is never silent) — closing the ADR-038 accepted limitation. Durable ledger (roadmap ② durability half): `SetLedgerStore` (wired from `INFERPLANED_LEDGER_PATH`, opt-in — nil keeps the in-memory posture byte-identical) loads persisted per-(rule, dataplane) spent/allowance into rules that still exist with an UNCHANGED period (the applyWire carry-forward rule) plus data-plane last-seen (so restored outstanding grants keep counting against the pool), then `handleSync` write-behinds the requester's rows each heartbeat in one transaction — a save failure logs (`onStoreErr`) and never fails the heartbeat, a LOAD failure fails boot (ADR-038 posture: claiming durability over an unreadable store is worse than not booting), and the 24h prune deletes the dead plane's rows; attach AFTER `AttachPolicyStore` so rows restore into the authoritative set. Rate shares (ADR-043, both halves): `applyWire` collects team rate rules (skipping unlimited and user-subject) into `s.rates`, and `handleSync` splits each rule's rpm/tpm among data planes live within 3× the heartbeat interval — HALF as an equal floor (an idle plane can always start working), half proportional to each plane's reported EWMA flow (`dpInfo.Flows`, replaced wholesale per heartbeat; no flow anywhere degrades to the v1 equal split); min-1 floor kept, Σ ≤ limit by construction, recomputed per heartbeat with no cumulative state, so a dead plane's slice returns to the pool within one horizon. Fleet version visibility (roadmap ③ phase 1): `dpInfo.Version` stores each heartbeat's reported build version and `/v1alpha1/dataplanes` exposes the distribution; `SetUpdateAdvice(minVersion, url)` (wired from `INFERPLANED_MINIMUM_VERSION`/`INFERPLANED_UPDATE_URL`) makes `handleSync` attach `updateAdvice` to any plane whose version is below the minimum per `version.go`'s `versionBelow` — lenient numeric compare, pre-release suffix ignored, and an UNPARSEABLE version ("dev", a git hash, or an old build reporting none) is stale by design. Advice only: the control plane can never push executable content, only this operator-set pin. `broker.go` (ADR-040) is the credential broker: `POST /v1alpha1/credentials` mints ≤1h STS sessions (`DurationSeconds` 3600 — role chaining's hard cap, since inferplaned's own task role is already assumed) tagged/named with the sanitized dataplane id. It is a `BrokerServer` with its OWN token and its OWN `authnBroker` check — deliberately NOT the shared `authn`, which also accepts verified OIDC console identities, and a browser SSO session must never mint AWS credentials; a JWT-shaped bearer is 403'd before any comparison. Mounted only when `INFERPLANED_BROKER_ROLE_ARN` is set (unset ⇒ 404, byte-identical behavior). STS sits behind the narrow `stsAPI` interface so tests need no AWS; an STS failure is a 502 with a FIXED body (the error text can name the role ARN, so it goes to the log only); a refused `SourceIdentity` (inherited from the task-role session) retries ONCE with session tags alone.
- `proxy/` — mayu's control-plane `Syncer` (heartbeat client), `LeaseTable` (the `Governor` lease gate: hard cap + expired/zero allowance fails closed), and `Syncer.Tiers` (`*tier.Table`, ADR-041) applied from `resp.ActiveTiers` alongside `Leases` — a control-plane outage keeps the last-received tier state, same posture as leases/policies. `LeaseTable` is keyed `(team, period)` and the gateway clamps each budget window against its OWN lease (ADR-042); `Syncer.SpentOf(team, period)` reports per-window spend — window-blind reporting would starve a daily rule's grant to zero once the month's spend passed its limit, because the control plane computes remaining = limit − reportedSpend. Window epochs (roadmap ②): each `Lease` carries the grant's `WindowID` plus a `BaselineMicroUSD` — the LOCAL counter reading sampled at an OBSERVED epoch change (never on first sight: mid-window attach keeps the conservative full report) — because the local counter rolls at the operator-timezone boundary while the control plane's window is UTC; reports send (counter − baseline) stamped with the epoch id, the gateway's lease clamp allows (allowance + baseline), and a counter falling below its baseline (the local boundary passed) resets it so the raw value is window-correct again. The sync report loop also skips user-subject rules (ADR-042 Phase 3): they hold no lease, so there is nothing per-user for a consumption report to carry. `Syncer.Version` rides every heartbeat (roadmap ③ phase 1) and `OnUpdateAdvice` fires when the control plane judges this build below its fleet minimum — once per DISTINCT advice, deduped across heartbeats (`lastAdvice`), so a 10s cadence never turns one stale binary into a log flood. `shares.go` (`ShareTable`, ADR-043) tracks `resp.RateShares` the way `LeaseTable` tracks leases: per-team most-restrictive fold WITHIN a batch, keep-last across batches (FailOpen — an outage never widens back to the global limit, never zeroes), and the gateway's team-lookup closure clamps policy rpm/tpm to min(limit, share) BEFORE `PolicyFromLimits` so the bucket burst follows; the clamp touches only dimensions the policy layer declares, making a stale share for a removed rule inert. The EWMA half (ADR-043 second half): `Syncer.FlowOf` (wired to `governance.Governor.FlowTotals`) hands the syncer cumulative settled-traffic counters per rate-ruled team; the syncer differentiates them per heartbeat, EWMA-smooths (α=0.5, `teamFlowState`), and reports `SyncRequest.Flows` — first sight establishes the baseline and reports nothing (a rate needs two samples), a counter restart re-baselines instead of reporting a negative rate. `credentials.go` (ADR-040) is `CredentialFetcher`, the broker client and mayu's implementation of `providers.CredentialSource`: a channel separate from both the heartbeat and the usage push, sharing only the base URL and carrying the DEDICATED `control_plane.broker_token_ref` bearer. Secret hygiene is a hard requirement here, and the three error policies differ on purpose — a non-2xx yields status code + a fixed string with the body drained unread, a decode failure yields a fixed string with NO `%w` (`time.Time`'s parse error echoes the raw value twice, and `expiration` is a field the response carries), and only a transport error wraps with `%w` (a `*url.Error` has no credential material).
- `cache/` — `VolatileStore` interface for in-memory-only payload caching / cache-affinity routing. **Not implemented** — no importers today; the routing rule's `Affinity` half exists in the wire schema ahead of this package (its `BudgetTiers` half, ADR-041, does NOT depend on this package and is implemented).
- `telemetry/` — usage wire types + window `Collector` + `Aggregator` (memory/postgres/durable), live (ADR-036). `proxy.UsagePusher` drains it to `inferplaned` on a channel separate from the enforcement-critical sync heartbeat.

## Design Debt
Worth knowing before assuming a caveat is temporary:
- **Multi-replica HA is designed, not built (ADR-013, still Proposed).** `keystore`/`providerstore` are SQLite-only; `limiter`/`budget` are memory-only; there is no Redis/Valkey dependency anywhere. Every "per-instance state" note above is a standing limitation, not a transitional one.
- **`cache/` (VolatileStore) is unimplemented** — see above.
